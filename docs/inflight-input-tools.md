# 运行中输入工具：按需操作

仅适用于已开启 v1 的当前已核本人、其发起工作中的飞书输入。其他参与人不继承开关；共享历史不会因此消失。普通补充问题沿原生回复处理即可，只有需要以下操作时读取对应一节。工具入口与核验仍由原 `input-trial` 实现承担，不增加读取、确认或调度流程。

## 查找输入、回执或中断问题

`node "$REMOTELAB_PROJECT_ROOT/cli.js" input-trial inspect --request-id <current-input-id> --json`

只在需要输入 ID、送达回执或未回答的保留问题时用。默认不返回正文，确需正文才加 `--include-text`；不会注入或重发用户输入。不要轮询，不例行重读整个对话。原生问题被中断时，旧按钮可能退役；保留未解决条件，只补读必要问题，仍必要才重新提问。插入消息、沉默和岔开的回答都不代表许可。

## 通过 outbox 回答补充输入

`input-trial reply --file <json> --json` 接受 `{sourceRequestId,replyId,requestIds,text}`。用稳定的 replyId 关联本人的一个或多个已接纳输入；结果不确定时先核回执，重试使用完全相同的包。沿已有 outbox 去重，不再在 reply 标签或 final 中重复同一答案。普通原生回复仍可用，同一答案只能走一种通路；主任务仍需最终结果。

新消息不要求单独回复。已有答案及时回答，可合并相容的问题；不为一个慢查询拖延已知答复。新信息改变判断时改稿。不要增加固定等待、草稿门禁、分类器、独立任务、并行答复工人或重复上下文注入。

## 本人明确要求停止整个当前执行

`input-trial stop --request-id <the-stop-input-id> --expected-run <current-run-id> --json`

只对明确停止整个执行的那条输入使用，沿原取消通路作用于匹配的 Run。取消一个步骤不调用整个 Run 停止。它不会更改参与模式，也不会停止外部作业；收到停止请求不等于已经终止，需核对实际结果。v1 没有并行答复工人或自动扣住草稿。
