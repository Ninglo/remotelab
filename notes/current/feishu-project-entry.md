# 飞书项目入口第一版

2026-10-02，Claude Tag 讨论提出：项目关联、自动任务、原始记忆和简单配置操作需要在飞书闭环。用户特别指出，展示不能维护一份容易过期的记忆副本。另一个讨论正在完整盘点记忆治理；本次沿用它已有的来源与状态边界，不重复实现治理层。

第一版以已有 `projectLinks` 为范围，登记记忆文件的准确标题、现有自动任务和关联资料。`/project` 在原话题创建一张持续更新的原生卡片。记忆页直接读取原文；任务页读取控制面的实际状态，可查看执行规则、暂停或恢复；修改记录保留操作者、范围、配置版本及读回结果。

记忆纠正通过 `/project memory 修改说明` 交回原对话，由 Harness 核对来源与并发变化，修改原账本并给出回执。提交请求不写成已生效。卡片观察同一来源的文件变化，包括原子替换。状态不可核实时明确显示缺口，不能拿旧缓存充当现状。

隔离场景已覆盖：来源范围与缺失处理、卡片投递重试、配置变化后拒绝旧操作、重复回调、暂停后恢复再暂停、结果不确定、重启后的去重，以及真实文件变化驱动原卡更新。现有自动任务 HTTP 生命周期测试、Connector 命令与路由测试通过。真实飞书投递及客户端按钮验收需分别记录，不能由这些隔离测试推断。

第一版只控制显式登记的循环任务，不发现全部组织任务，也不建立组织共识。共享日报和消费者要显示真实共享范围；暂停不会停止已经运行的工作。整体记忆治理继续按原审计方案处理。
