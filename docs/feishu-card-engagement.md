# 飞书卡片使用数据

目标是依据实际使用情况，为用户推荐适合的飞书工作流。采集和推荐分开：目前记录行为并提供汇总，尚不自动生成偏好、修改设置或发送推荐。

现有进展卡片的回调记录展开、折叠以及“卡片＋新消息 / 只更新卡片”的选择。先核对原卡片、来源应用、话题、操作者和权限，再记录回调的接受或拒绝结果。同一个飞书事件重试只计一次；点击次数和点击过的卡片数分别统计。飞书缺少事件编号时优先使用回调 token 的哈希；再缺 token 时按按钮版本去重，可能低估重复点击。

阅读信号来自飞书消息已读接口，以及应用已订阅时的单聊已读事件。群卡片通过现有连接器的投递长轮询间隙逐张采集，每次最多请求一页；同一张卡片完成后最早五分钟再查，实际间隔还取决于卡片数和连接器事件量。只查询本应用已经发送并留有回执的卡片，限发送后七天，过期停止查询。较早回执先核对消息发送时间。永久权限或业务错误留存后停止自动重试；修复对应权限或业务条件并核对新证据后，移除对应采样失败条目才重新采集。网络或限流失败最多连续尝试三次，不影响收发消息。

使用已认证的 `GET /api/usage/analysis?days=7` 查询；可加 `sessionId`，返回的 `feishuCards` 包含全窗口汇总，不受最近原始事件的 `limit` 限制：

- `byUser`：按已核 Person 合并；尚未绑定 Person 时按应用内用户的哈希区分。
- `totals`：展开/折叠次数、各投递选项次数、失败点击数、已读/点击/展开过的用户与卡片组合数量。
- `sampling`：后台采样状态、失败和未完成分页。此状态为实例范围，即使查询按 Session 过滤也不代表该 Session 已全部采集。

数据沿用实例 `usage-events/` 的事件存储和去重规则，文件权限 600。采样状态在 `feishu-card-reads/<来源路由>.json`；只存卡片哈希、时间和采样状态。行为记录不保存消息正文、思考内容、回调 token 或原始用户 ID。已核的身份可以关联同一个 Person；不同应用中碰巧相同的 open_id 不自动合并。

已读不能证明认真看完；展开后的停留时间无法可靠获得。群卡片共享展示状态，别人展开后直接看内容不会新增本人的展开次数。没有点击或已读信号时应保留“未知”，不能当作“用户不关注过程”。推荐可以比较一个人在不同任务类型上的行为，并通过明确反馈验证；不把观测直接写入人员偏好。

官方接口：[消息已读查询](https://open.feishu.cn/document/server-docs/im-v1/message/read_users)、[单聊消息已读事件](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/events/message_read)、[卡片交互回调](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-callback-communication)。
