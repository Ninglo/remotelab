REMOTELAB · ARCHITECTURE ATLAS

用户发出一条消息后，系统里发生什么？

一句话：入口接收输入，RemoteLab 按规则保存状态；需要正式执行的任务交给 Harness，结果通过原入口回到用户。

这张网站按当前源码与本实例的部分配置、运行记录编写。总图用于定位责任；下方选择具体路径时，时间顺序、跳过的步骤和成本以该路径为准。

两个不同的 token

模型 token 是输入、缓存输入和输出的用量；飞书应用 access token 是 API 授权凭据。固定程序本身不消耗模型 token；程序若调用 Jev 或 Harness 则另计，发飞书消息还使用接口配额。

这张网站如何持续更新

  1. 每个机制只有一份数据条目；全景、路径和证据视图引用相同的 ID。
  2. 修改代码时更新对应节点的调用链、状态和相关路径；标记所依据的源码版本。
  3. 实例运行事实单独注明配置与核对时间。一次配置成功、一次模型输出和用户实际收到结果分别记录。
  4. 保留被新证据替代的判断，记录为何修改；没有证据的环节保持“待核验”。
