RemoteLab 文档

使用与机制

在 RemoteLab 里，你通过对话把工作交给 Agent。它在真实机器上使用工具，保留工作记录，再把结果送回你发起任务的地方。

一次工作可能从“帮我整理这份资料”开始，中途又加了一个条件。你离开页面以后，还要能回来查看进展和结果。沿这条工作路径往下看，可以找到消息记录、实际执行和交付各自的位置。

从哪里开始

第一次看，先顺着下面的工作流程走一遍，再进入执行章。排查问题时，可以直接用章节目录找相应环节。需要字段、接口或源码时，打开段落旁的展开项；左侧的“展开研发细节”能一次打开它们。

研发查阅与实例路径

说明里的源码链接对应各条目自己的核对基线。查看当前运行状态，还要读实例的 build-info、配置、业务记录和投递回执。各章保留自己的日期；网页改版没有重新验证所有运行功能。

配置目录和记忆目录通常分别是~/.config/remotelab与~/.remotelab/memory，实例环境可以覆盖。完整实例路径和私人资料在登录后主动读取。

编辑、发布和恢复的具体步骤
  1. 修改原内容源。生成型README用对应render-reference.mjs更新；维护规范README直接编辑。
  2. 运行node docs/architecture-atlas/assemble-site.mjs <空输出目录>。它复制允许的静态文件，调整外置记忆章的相对路径，再从目录生成五个页面的导航。
  3. 检查链接、图表交互、桌面与手机阅读、无脚本导航和公开信息范围。按仓库main／CI规则交付源码。
  4. 运行remotelab publish static --source <输出目录> --slug remotelab-architecture-atlas --replace --json更新原网站，然后匿名回读页面。
  5. 备份source/、site/、manifest.json、SHA256SUMS与RESTORE.md。从备份源码重新构建，检查输出一致。

JavaScript 数据文件保存说明条目，不是记忆数据库。Markdown适合维护可读文字；JSON保存结构化配置；JSONL保存逐行事件。文件格式与项目、人员、公司等业务归属是不同维度。

遇到问题时怎么查

  • 消息发出后没有动静：先看输入是否收录，再查 Request 是否被接纳、Run 是否开始。
  • 工作做完了，却没看到结果：核对任务验收和投递回执，检查结果应回复的位置。
  • 明明记过，下次还是没用上：查读取入口、当前身份和项目范围，再看本轮是否读过正文。

怎样看待状态标记

“源码已核”说明代码中有实现，“配置已核”说明某个实例当时有这项设置，“运行样本”说明一个具体案例发生过。目标方案和待核项保留各自标记，不能从一张完整的图推断功能已经上线。

实际使用发现问题，就沿对应环节修正。旧样本保留日期，被替代的判断保留修改原因。任务状态和业务事实仍在原系统维护。

验收时分别需要哪些证据

代码测试、部署版本、真实输入、工具或业务结果、外部回执，以及用户是否达成目的，各有对应证据。说明网站的检查覆盖文档与网页交付，不能替代运行功能的验收。
