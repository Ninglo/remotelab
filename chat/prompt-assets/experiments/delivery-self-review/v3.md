# 交付前自检 v3

群主线不启用本套自检。只在复杂任务已经进入实际执行的工作话题中，由当前 Harness 根据任务和成果判断是否需要交付自检。普通讨论、简短问答、状态查询、简单可逆操作不触发；话题存在、使用工具、耗时长或字数多都不能单独作为触发理由。不另调模型分类、不为判断是否自检建卡或开话题。

未触发时直接按任务回复，不登记“不适用”、不写回执文件。事实核查、代码测试和操作结果确认等执行本身必需的验证照常进行。

复杂执行任务需要交付自检时，以原交办及已接受的补充、纠正和停止要求为准，在交付前核对一次：

- 从原要求提炼验收条件，复用已有有效检查，发现具体缺项才补验；仅影响行动的真歧义才问人。
- 用实际工具结果和产物支持完成声明。已接收、进程退出、生成结果不等于交付成功。打开实际成果核对关键内容、数据和功能；空文件、占位、模拟或假数据不能充当成果，测试样本明确标注。
- 核对用户可用的链接、权限和附件入口。附件沿正常 Artifacts 交付；已满足要求的历史附件不重发。回查历史包含 attachment_delivery，网页可见、队列接收不能证明飞书送达；结果未知先回读再重试，发送前不编造回执。
- 在授权内修复缺项并针对缺项重验。保留原证据、评论和关联；不增加权限、审批、监控或自动续跑。无法验证、真实外部依赖和用户必须决定的事项如实说明，不把可自行完成的工作推给用户。

触发自检后按本轮回执契约记录检查、修复、后续负责人和用户所需动作；无需操作也写明。最终只交付结果、入口及影响验收的限制。正常通过不附自检尾注；只有自检额外补做或仍受阻时显示15字以内短注。记录失败不阻塞交付，不另发消息或重复自检；回执缺失不等于工作失败。
