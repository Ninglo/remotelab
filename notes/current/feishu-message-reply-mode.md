# 个人消息回复设置

Settings 的「Message／消息」属于当前登录的人。网页身份和飞书身份绑定到同一个 Person ID 后，本人在网页、飞书私聊、普通群和群内话题发起的工作使用同一份回复设置。没有群选择、Bot 选择或全员开关，其他人的选择独立保存。

页面的回复展示提供三个可选部分：首条文字回复、按需任务清单、过程进展。进展打开后有三种展示方式：

| 方式 | 卡片中的进展 | 独立文字进展 |
| --- | --- | --- |
| 卡片＋单独文字进展 | 显示最新一条 | 逐条发送 |
| 卡片展示最新进展 | 新进展替换上一条 | 不发送 |
| 卡片展示全部进展（默认折叠） | 全部记录在折叠区内，包括最新一条 | 不发送 |

三种方式都保留一张卡片。有任务清单时更新清单原卡，没有清单时使用进展卡。网页使用同一语义的内联卡片，飞书使用原生卡片。第三种在网页完整展开记录，在飞书内容较多时于原卡内翻页；后续更新保留同一张卡的展开、折叠选择。共享群卡的展开按钮影响这张共享卡，不修改任何人的个人设置。

修改选项只更新本地示例，点击「保存并应用」才保存并启用。无需另存草案、选择群或再次确认。「恢复默认」仅清除本人的自定义方式，保留默认卡片的现行控制。未保存的人继续使用当前默认机制；原先已经确认的按群配置和历史请求保留兼容，不从原群设置推断任何人的个人偏好。

首条文字是收到较长任务后说明理解和第一步的回复。简单问题可以直接回答。允许任务清单不要求所有工作都创建清单。关闭过程进展仍可保留清单；必要提问、异常通知和最终回复始终独立展示。群参与、旁听、暂停与资源权限沿用现行规则；个人分流选择见下节。

## 保存及生效

`GET /api/message-reply-settings` 只返回当前登录人的设置，没有群目录。`POST` 接受 `apply` 或 `reset`，使用本人登录身份、`expectedRevision` 和 `confirm: true`；`apply` 另带 `choices: { opening, checklist, progress, strictStartCheck, routing }`。请求不能指定另一个 Person，服务账号不能操作个人设置。

设置通过现有 People 存储的 `preferences.messageReplies` 持久化，原子更新保留其他偏好和其他人的记录。每个人分别维护版本和更改记录。普通网页和经过认证的飞书输入在受理时按实际发送者读取设置，保存 version 3、scope person 的请求快照；不采用 Session 创建者、Bot 身份或机器账号作为发送者。

保存影响后续新工作。正在运行的工作、重试、原生追加输入和同一工作的分流延续保留开始时的设置，原卡继续按创建时的方式维护。新选择不会重放历史进展或为已结束的工作补发卡片。网页可展开的原始过程记录仍完整保留。

## 验证边界

实现复用现有 Person、Session、Request、原生消息事件、投递记录和卡片 worker，无额外模型调用。`tests/test-person-message-replies.mjs` 验证个人隔离、四类入口、持久化、并发版本、身份校验、三种展示与关闭选项、提问与最终回复。真实 HTTP 回归验证网页、私聊、普通群及话题受理后的同一快照，以及重试和恢复默认。浏览器验证本人保存、重新载入和不同登录人的隔离；真实飞书消息投递及真人使用体验需按自然发生的消息观察。

个人保存和恢复默认同时更新现有使用统计中的个人配置状态，记录选项与作用范围，不保存原始身份、聊天名称或消息正文。历史群级配置的统计保留兼容，不作为当前个人配置。

## 消息分流选择（2026-10-10）

Message 中的「分流机制」有两个固定选项：不分流（默认）和实验分流。没有保存过设置或旧设置缺少 routing 的人默认不分流；不根据试点群配置推断个人已选择。routing 取值为 none 或 experimental，和首条回复、清单、进展、开工严格检查一起保存；单独切换严格检查或旧客户端只保存展示选择时，保留已选分流机制。恢复默认同时恢复不分流。

不分流时，消息在当前绑定会话处理并回复。实验分流复用现有机制：在已启用的飞书试点群中，主线尽快安排新事项到工作话题，同事项补充接续原工作，兼容输入可以追加到活跃执行，催问可按原消息地址先答复。选择不增加试点群、资源权限或跨话题同步授权；跨话题复核仍须确认具体草稿。网页、私聊和未启用试点的群不自动转接。

分流按每条新接纳的消息读取实际发送者选择，独立于同一原生执行继承的展示策略，以免一个人的实验选择替另一人开通分流。受理时保存 messageRoutingPolicy 快照；不同机制的输入不共用有冲突指令的原生执行。重试、已转接的工作包和问题答案保留受理时的契约；已有运行与原话题不被搬移。未带快照的旧请求保持原契约。关闭自动分流不取消已经提出的具体同步草稿，人的明确确认或拒绝仍按原授权核验。

禁用状态同时影响提示和 work route／work reply 的服务校验，批量转接不能夹带禁用输入。验证使用隔离 People、试点配置、真实受理和假执行器，不向实际群发送测试消息。自然群聊的分流准确率和速度仍按原实验的观察范围验收。
