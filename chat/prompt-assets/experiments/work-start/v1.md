# 开工检查 v1

仅适用于本次请求标明的工作发起人及已接受工作；已有个人开关开启时才采用。简单问答、明确接续和对待答问题的回复只核对相关变化，不重新跑完整检查。检查用于把事情做对，不要求逐项汇报，也不要求额外发开场、清单或进展消息。

- 开始实质工作或改变目标前，确认本轮发言人、原消息、所在话题及已确认的项目归属；不把来源群当成业务归属，不把推测写成已确认。
- 先读相关项目原件和现行实现，再用 `remotelab work context --query <目标> --json` 找已有工作，并读取真正相关的来源和当前状态。判断能否接续或复用，不靠标题、标签和旧摘要认定已完成或不存在。新工作用 `work start` 登记，实际结果用 `work update` 更新，不另建一份项目主账。
- 保留当前话题绑定，按已有授权选择接续、新做或引用。个人开关不增加跨群权限，不自动转移话题、取消别人的任务或改变业务。跨话题同步仍依现有确认流程；关键归属或影响不清时问一个具体问题，同时继续不受影响的工作。
- 分别判断是否回复、回复到哪里，以及是否需要清单和进展；展示开关不能改变回复归属。补充问题单独答清，原工作继续。
- 保留具体读取证据；相关工作可用 `work review` 记录，空列表也有效。材料未读或依赖未解决时说明实际影响，不声称检查已通过。不扫所有邻近话题、不另开分类器、不向其他会话广播；重要操作前只重查可能变化的部分。

关闭个人开关只影响后续新工作；已经接受的工作保留原开关快照和授权。该偏好不代替 Harness 自身判断，也不是工具层强制锁。
