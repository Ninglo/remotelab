# Codex account and quota status

Settings → Codex login now shows the current account's display name (when supplied), email and plan. API-key sign-in is labelled explicitly. Quota loads independently so a slow usage endpoint does not delay identity or the login controls. Identity reads have a 12-second deadline; remote quota reads allow up to 45 seconds (live transport can exceed 25 seconds). Each supplied quota bucket shows remaining percentage, its actual window duration and reset time, plus the observation time. Unknown windows do not become zero; elapsed reset times request a refresh rather than implying a renewed balance.

The only Codex RPCs are `initialize`, `initialized`, `account/read` with `refreshToken: false`, and `account/rateLimits/read`. No thread, turn, prompt, model, AI session, scraping, or usage estimation is involved. Protocol reference: https://learn.chatgpt.com/docs/app-server#auth-endpoints . Codex remains the authentication and token-refresh authority; RemoteLab never refreshes grants itself.

`lib/codex-account-status.mjs` implements a bounded stdio exchange with the installed CLI and the same resolved Codex home as the instance. It returns an allowlist of public fields. A local ID-token name is display-only and only joins a matching RPC email. Tokens and raw provider errors are never returned. A credential revision prevents combining a query with a login changed while it was in flight; the UI also discards earlier request generations and mismatched account revisions. Missing names remain missing.

The existing authenticated `/api/codex-auth/status` adds `account` and an opaque `accountRevision`. `/api/codex-auth/rate-limits` returns `codexUsage` independently. Both are private/no-store HTTP responses. Usage has a process-local 60-second cache bound to the resolved home and credential revision, concurrent requests share one query, and explicit Check status requests bypass the cache. Keyring-backed accounts without a local revision are not cached. Logout invalidates cached usage. Missing/failed usage is visible and retryable; API-key or other non-ChatGPT auth reports that subscription limits are unsupported.

Validation: `test-codex-account-status.mjs` exercises safe projections, multiple buckets, missing fields, exhausted windows, changed accounts, mismatched local names, errors, timeouts, cache invalidation, single-flight reads, logout and owner authorization. `test-codex-account-settings-ui.mjs` executes the UI in a VM to verify literal identity text, both languages, quota formatting and stale-request rejection. Existing device-login/logout and account-switch tests remain in the merge-safety suite. Installed-CLI checks use only the read-only methods above.

## Saved accounts and subscription failover

Settings → Connections → Codex now lists saved accounts. Adding an account starts an independent device login and keeps existing accounts signed in. Selecting a saved account changes the default for subsequent runs; a running turn retains its selected account. Explicit logout applies only to the selected account and is refused while that authorization is in use. API endpoints add `GET /api/codex-auth/accounts`, `POST /api/codex-auth/accounts/policy` with a boolean `autoSwitch`, and an optional `accountId` for selection or reauthorization. No endpoint accepts credential material or filesystem paths.

The instance-local `config/codex-accounts/accounts.json` stores the list and policy. The original Codex home is the default slot. New account homes hold separate, continuously refreshed credentials while sharing local conversation files and instructions. This is an account selection mechanism, not token backup/restore. The policy defaults off until enabled for that instance.

With automatic switching enabled, admission queries live subscription windows. A confirmed exhausted account is skipped; a backup needs a fresh, positive, matching Codex/model allowance. An unknown balance never means zero or renewed quota. A selected account with a temporarily unknown balance can continue; a transport or sign-in error never triggers post-failure rotation. Only an explicit subscription-exhaustion response permits a bounded retry with another identity, resuming the saved native thread. If tools already ran and there is no saved thread, RemoteLab stops instead of replaying the original request. API-key logins are not subscription fallback candidates.

Every account authorization has a cross-process lease. Independent account homes can run concurrently: automatic selection considers free accounts with confirmed allowance before queuing behind a busy account. A single authorization executes one owner at a time. Device login, account reads, quota monitoring, background helpers and foreground execution use that same lease. While a native run owns the authorization, quota is read through its existing App Server rather than another process; sanitized samples are persisted for observers. `scripts/codex-account-observe.mjs` allows the local fleet adapter to read/refresh idle profiles under the same lease. An imported monitor home is adopted in place; its previous collector must be marked externally managed before enabling runtime use. All configured consumers must honor this ownership boundary; external CLI jobs using the same home do not automatically join the lease.

Validation includes isolated batch and native exhaustion after an already completed tool action: the next identity resumes the saved thread and that action occurs once. Tests also cover restart persistence, independent logins, stale/unknown quota, duplicate subscription identities, busy observers and rejection of network/auth failures as rotation signals. Real-account validation must separately confirm that the installed CLI can resume shared local conversation files across account homes.
