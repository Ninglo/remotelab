# 员工档案与 Agent 行动手册

让负责这个实例的 Agent 接手时，可以这样说明：

> 在当前实例启用人员协作记忆和行动手册。先核对实例、当前消息的 Person 身份和现有记忆治理；只开放指定人员试用，不批量认领旧 Inbox。保留人工正文和原始证据，验证普通习惯、明确偏好、真实权限缺口、撤销和新旧 Session 的读取。报告代码、配置、服务加载和实际使用分别确认到哪一步。

一次提供目标实例和参与试用的 Person ID 即可；Agent 自行完成代码、验证、配置和回读。安装代码默认关闭，不增加 UI、前台模型调用或定时整理器。启用不修改 AGENTS.md，也不扩展业务授权。

核心原则继续由人维护。后台沿用现有一次回合结束评审，从用户原话、当前 Run 的工具结果和已有条目提取具体经验，同时保留原有重要事项的候选收集。后台仍使用原来的独立成本配置；前台 Harness 负责理解任务和选择行动。

| 内容 | 唯一维护位置 | 自动维护范围 |
| --- | --- | --- |
| 称呼、表达方式、协作习惯 | `MEMORY_DIR/reference/people/<personId>.md` | 保留人工正文，在受管理区维护观察、明确偏好、反例、证据与版本 |
| Agent 的具体行动方法 | `MEMORY_DIR/reference/agent-handbook.md` | 有工具证据的方法可自行验证、修订；条件、例外与授权边界随条目保存 |
| 核心原则与业务授权 | 原有公共／仓库 AGENTS.md 等入口 | 本功能不提供写入目标 |
| 项目状态和重要决定候选 | 原有主账及 `writeback-targets.json` 允许的候选目标 | 继续既有流程，不复制到个人档案 |

人员身份取自该 Run 已接纳 Request 的 `viewPersonId` 和 `initiatedByIdentityId`，并核对认证目录中两者的关系。不继承 Session 创建者、机器用户名或被提及的同事。人员档案用来说明怎样合作，不对个人性格作诊断；项目参与和进展仍查原主账。本版没有批量生成全员项目履历。

## 从观察到可用经验

### 个人学习的按需操作指南

默认上下文只带本人学习开关、触发条件、确认边界和本节入口。发现具体协作反馈时，在本轮读取本节及下文写入格式，再调用 `remotelab memory inspect --json`。档案正文与教学示例不随每条消息注入。固定说明单独参与按身份、版本及接收回执去重；开关变化须送达，新的写入反馈仍留在每轮上下文。新线程或无法确认旧规则已被接收时重新提供短说明。

1. **先判断归属。** 称呼、讲解方式、配合方式等个人协作需要可进入本人档案。产品功能、界面要求、项目决定和验收条件留在原项目；反复提出、写成 `observed` 或加“仅本次”都不能改变归属。归属不清先留原对话。
2. **提炼可复用的含义。** 保留协作需要、决策顺序和原话语气；“可以”不能改成“总是”。机器、项目、录音等来源场景不自动成为适用限制；本人明确限定及维持原意所需的条件必须保留。用相邻场景检查含义是否仍成立。措辞须让本人脱离原对话也能理解，让 Agent 知道下次应如何调整；不只写“提高效率”或一个工具名称。
3. **比较既有含义与范围。** 相同已确认项直接采用，不重复写入或提问。新增范围另作候选，不能扩大已有确认项或业务授权。来源保留原话、作者与实际证据；“强调很多次”只是本人报告，不能虚构多次独立观察。
4. **区分观察、提议和确认。** 一次具体信号即可记录 `observed` 并提出未来使用；三个独立 Session 的支持只使其成为软建议 `inferred`。本人明确指定长期要求及范围可直接 `confirmed`；仅纠正当前任务则先保留观察，再问是否用于以后。沉默、含糊应答、认可一次观察准确都不是长期确认。
5. **沿现有写入流程处理。** 用本轮原始证据和当前版本提交；询问前用 `propose` 登记确切问题、含义和范围。已有 pending 不重复问、不擅自改意。本人明确决定后沿原条目修订或撤销，版本冲突先重读；失败不声称保存成功。提议信号在工作中出现即可处理，不必等整个任务结束。

以下为合成示例，不是当前用户的事实：

| 信号 | 保留的含义与边界 |
| --- | --- |
| “需要我配合时可以用扬声器叫我” | 可用声音提醒本人配合；不限制为当时那台机器，不推断听力问题，也不许可所有通知播放声音。 |
| “只有这通电话轮到我时响一下”；“设备录音开始必须响” | 前者仅本次；后者是产品要求。均不自动变成个人长期偏好。 |
| “陌生术语让我跟不上，联系熟悉的东西讲” | 解释陌生概念时先用熟悉例子；不推断讨厌技术细节。若明确说“仅学习 API 时”，保留该范围。 |
| “反复试改时先考虑怎样方便查看和反馈，不要每轮默认发压缩包” | 先考虑查看与反馈便利，再选交付方式；不简化为讨厌压缩包，也不强制发网页。 |

### 开关、询问与反馈

仅实例试点名单中的本人可开启会话学习；按当前发言人身份应用于 Web、飞书私聊、群及话题。其他成员、机器人和自动任务不继承。已开启且经连接器认证的本人群输入，可复用原有一次轮末评审；后台不独立发送消息或新增提醒。

开启独立记忆核验卡时，使用现有 outbox，不在任务答复重复提问；卡片答复只处理记忆，不打断原任务。未开启卡片时，在记录提议后的下一次有用答复中至多补一句自然询问，不另发私聊或卡片。紧急任务或群隐私不适合展示时保留观察，卡片路径可用 `deferReview:true`；稍后明确 propose，不提前占用未发送问题。未回答不催问，不暴露别处的私有事实。

成功保存明确长期要求后简短说明实际保存内容；卡片候选无需重复播报。启用对话试点时，实施者应停掉该人此前获授权的独立核验订阅；网页开关不擅自取消其他任务。“停用个人记忆”停止该人的后续自动观察、查询和询问，保留已有记录与历史；显式撤销、项目记录和 Agent 手册仍沿各自流程。

后台真正进行记忆提取时仍使用 `chat/memory-abstraction.mjs` 的方法与例子；前台改为按需读本指南。来源和版本检查不能证明语义判断正确，仍须用真实纠正检验效果。此前参考的 [Claude Tag 公开说明](https://claude.com/docs/claude-tag/users/memory)（2026-10-16）支持短笔记与人工纠正，但未公开提取算法；其频道／工作区归属不替代本系统的 Person 归属。

Agent 方法从 `observed` 开始。后台判断方法实际经过执行，再引用该 Run 的成功工具结果，才能成为 `verified`。进程退出码零不能覆盖 API 里已知的失败响应；来源不存在、原文引述不匹配或实际失败都会拒绝激活。模型负责判断证据是否支持方法，代码检查来源、结果与版本；两者仍可能漏判，反例会暂停默认使用。

例如，经验应保存“判断飞书权限前核对当前 Bot、接口错误、用户 OAuth／资源访问，并检查已授权备用入口”，附上适用条件；一次调用成功不证明永久有权限。真实缺少 scope 的结果仍是失败证据。具体方法无需逐条让人审批，但不能从一次成功推导出新的业务授权。

相同语义沿已有 key 合并证据，保留独立来源。同一事件重处理不增加观察次数。改变含义须用 `revise` 和当前版本；本人偏好的修改／撤销须有本人明确来源。撤销条目保留 `withdrawn`，不允许后台自动恢复。反例使用 `counterexample` 后降为观察，新的验证修订可以恢复适用方法。每次修订保留旧版本、原因和来源。

Agent 可以根据原话自动细化尚未确认的习惯观察。含义或适用条件改变后，新判断重新累计支持证据，旧条件、例外和证据留在旧版本，不能把旧观察次数套给新判断。

本人明确修改旧人工档案时，用 `supersedesManual` 引用被替代的原句，保留原文并标明新版本或撤销优先；旧人工正文不能继续盖过本人新要求。明确要求恢复已撤销条目时，可使用 `restore`、当前版本和本人原话；方法恢复还要有新的成功执行证据。后台重复观察不会自动恢复撤销内容。

## 独立记忆卡片试点（飞书）

经本人明确选择后，实例可在 `learning-policy.json` 的 `reviewCardPersonIds` 中列入该 Person（仍须同时在 `personIds` 且开启个人记忆）。其他成员及网页对话沿用原自然答复方式。飞书新记忆写入或前台 `propose` 后，复用原请求的已认证身份和投递地址，通过现有 outbox 发送一张独立卡片；普通历史观察不会批量补发。不另开核验私聊、日程或模型。

卡片默认只显示一条记忆总结和简短状态；候选提供“保留”，并可“修改”或“不记这条”。点击修改后才显示完整记忆、适用时机和例外；取消不改记忆，保存后收回总结视图并明确显示“已保存修改”。保留将候选确认为本人偏好，修改保存本人提交的完整内容及范围，不记保留撤销历史。已明确确认的新记忆标为“已记住”，仍可修改或撤销。每个记忆保留首次卡片地址，重复投递复用同一张卡；跨话题不复制个人记忆。原来“不得另发卡片”的自然答复规则仅对这项已选试点让位，不重复在主任务中询问同一候选。

这是一条独立交互线：投递使用不运行模型的 delivery-only Request；点击直接走现有记忆版本写入和来源审计，不提交聊天输入、不唤醒或中断原 Run。未回答、晚回答及卡片故障均不把原任务设为等待。原任务需要改动时由人另行提出。卡片操作核对本人、Bot、租户、原消息及条目版本；过期版本刷新后重新决定。保存后的可见状态通过原消息更新接口持久化，同时返回卡片回调；卡片刷新失败会明确说明记忆已保存，再点重试不重复写入。已成功写入但回执丢失时根据审计来源恢复，不重复修改。原文与修订历史保留，其他人点击不披露新的档案内容。

启用后，前台和后台共用原提取与写入机制。卡片只负责展示和确定操作，不判断候选是否值得记忆；归属、抽象粒度和隐私仍由 Harness 判断。紧急或不宜在当前群展示时，在该项 `memory apply` 更新中设 `deferReview:true`，只保存观察，不发送卡片；之后时机合适再明确 `propose`。暂停个人记忆后不再生成卡片，旧卡保存操作也拒绝，历史记录保留。

## 保存后的自然反馈

前台遇到明确的长期个人要求，按原证据写入并核对成功后，在当前普通答复中简短说明实际保存的内容；失败、候选、待回答不能称作“已经记住”。同义且同范围的已确认项直接应用，不每次重复宣布保存。是否属于个人、是否值得提问、是否已确认仍分别判断。

后台评审可能晚于最终答复完成。对已启用对话试点的本人，下一次同一话题输入可携带最近后台确认或撤销的最多三条 ID、版本、状态及来源序号，前台读取现行条目后，在合适的普通答复中补一句保存或撤销反馈。不复制档案正文，不向其他话题或私聊推送；普通未启用用户不增加历史读取。暂停、自动化输入、Bot 输入继续排除。

这个补充入口只读取最近 64 个事件，并在上一份前台上下文处停止；下一轮不反复投影。它提供一次自然反馈机会，不是用户送达回执：历史过长、后台较晚完成、插入其他人的回合或本轮紧急工作可能使反馈延后或错过。旧写回事件缺少本人归属标记时不追补。不要据此宣称每条后台记忆必定通知；用真实自然对话另验表达、送达和后续应用。

前台短规则保留触发、归属、范围、确认和反馈，详细写入参数集中在本页。隔离模型对照应冻结原话、提供同一份当时可见的记忆状态，比较旧新规则；重复样例与写进提示的样例分别标记。结构化决策回放只能检查识别与拟采取动作，不能替代完整工具执行或人的使用验收。

## 实例怎样启用、怎样退出

Agent 在实例的 `MEMORY_DIR/learning-policy.json` 保存明确授权范围：

```json
{
  "version": 1,
  "enabled": true,
  "profiles": true,
  "handbook": true,
  "context": true,
  "personIds": ["person_example"]
}
```

Person 必须存在于本实例的认证目录。文件缺失、配置损坏、未列入的 Person 均不启用这套学习；未参与试用的回合仍走原来的候选写回。现有候选目标允许名单不改变。`REMOTELAB_MEMORY_WRITEBACK=0` 继续关闭后台写回；`context:false` 关闭显式查询中的本功能正文投影；普通回合始终不自动投影这些正文。关闭后，旧原生线程可能还保留已见信息，不能宣称历史上下文被删除；撤销条目时，下次显式读取会返回新的撤销状态。

无需重启即可读取配置变化。使用 `remotelab memory status --json` 核对实际实例；不要把源码默认值当成配置或其他实例已启用。

## 按需读取什么

普通新线程和续接线程只收到当前已核 Person 的档案指针，不自动读取人员正文或按关键词投影方法。Harness 按任务需要读取原档案、手册，或调用 `remotelab memory context --query <topic> --json`。显式查询只读取已核 Person 的有限正文及与查询匹配的方法，最多 12 条、总量不超过 6000 字符；条目连同条件、例外和来源整体进入，放不下就跳过。较大的人工旧档案继续通过原文件指针按需读取。项目方法只在既有项目配置明确关联到同一个项目时读取；不按 Session 标题、工作目录或侧栏分组推测项目。关联缺失或涉及多个项目时，不晋升一个项目方法为实例通用方法。

显式查询返回正文、ID 与版本，并以 `read_memory` 记录检索交付；普通 `manager_context` 不再携带这些条目。下一回合的原话纠正、反例或工具结果可以反馈到原条目；`outcome` 必须对应本轮实际传入的条目，并有原始证据。它是模型整理的使用反馈，不是独立实验的因果证明。没有反馈不代表成功；最终是否减少误判和纠正次数，仍需观察真实任务。

关键词检索是首版实现，尚不能保证召回所有表达变体。遇到新场景或执行中才发现权限问题，Harness 可以运行 `remotelab memory context --query '飞书权限' --json` 按需查阅，而不把整本手册塞进每轮上下文。核心原则、人当前明确要求和现场能力证据继续决定行动。 显式查询还可按所给主题读取已登记导航、任务入口和启用的项目主账中的有限原文；项目关联缺失不会被当成资料不存在。来源、预算与参考边界见 `docs/session-work-awareness.md`。

## 对话中的检查和修订入口

`remotelab memory inspect --json` 显示当前请求者档案、行动手册、观察状态、证据和修订历史。默认从 `REMOTELAB_RUN_ID` 找实际请求身份；没有可核身份就拒绝写人员档案。这里的身份是归属，沿用共享实例的完整访问权，不新增 Session 私有权限。

个人开关 API 为 `/api/personal-memory-settings`，只接受本人登录身份；对话操作使用 `/api/personal-memory-settings/current-run?runId=<当前运行>`，从已接受的当前人类请求核对身份。POST 需要 `enabled`、`expectedRevision`、`confirm:true`（对话入口另带 `runId`），不接受调用者指定另一个 Person。关闭后旧模型历史不会被清除。

对话提问示例：`{"updates":[{"key":"familiar-example","kind":"habit","action":"propose","expectedVersion":2,"question":"我观察到你理解陌生概念时更容易从熟悉的例子入手，要不要记下来？","evidence":[{"seq":42,"quote":"当前本人消息中的真实原文"}]}]}`。必须先有同 key 的未确认条目，并使用真实版本及证据；不是让后台自动新建或发送这个示例。随后 inspect 可读取 `reviewProposal`；确认时比较问题保留的含义和范围，不能把对旧问题的回答用来接受一个已改写的新偏好。

需要立即纠正而不等待后台回合结束时，Harness 从当前原话及工具证据制作更新，运行 `remotelab memory apply --file <updates.json> --json`。例如本人明确撤销时：

```json
{
  "updates": [{
    "key": "plain-language",
    "kind": "preference",
    "action": "withdraw",
    "expectedVersion": 3,
    "explicit": true,
    "reason": "本人撤销",
    "evidence": [{"seq": 42, "quote": "不要再默认用大白话了"}]
  }]
}
```

seq 和 quote 必须来自本次 Run 的真实原文，版本从 inspect 读取。新条目使用 `upsert`，省略版本；`kind` 为 `preference`、`habit` 或 `method`。方法另带 `scope:instance|project`、`tested`，并提供 `content`、`cues`、`conditions`、`exceptions`；项目 ID 由可信来源配置决定。先前相同 key 的个人观察可用明确修订升级为偏好，不生成平行条目。

受管理区用同一 Markdown 文件里的可读正文和结构化注释保存条目，保留其前后人工内容。写入使用异步原子替换、文件锁和版本前提；损坏、冲突或遗留锁会保留原文件并报告拒绝。实际后台结果进入本轮 `context_operation` 审计。人工维护者不应同时手改受管理区；文件锁只协调遵守协议的写入者，不能保证所有外部编辑器都参与锁定。
