# 会话元数据目录

会话历史仍保存在原事件存储中。元数据兼容旧 `chat-sessions.json` 数组，也支持显式迁移后的“小索引＋独立记录”：索引保存顺序、记录哈希和版本，每个会话正文位于 `chat-sessions.json.records/<sha256>.json`。按 ID 查询只读取索引及目标记录；列表查询才读取全部正文，未变化记录共享已解析对象。批量修改必须替换被修改记录，不能原地修改共享快照。

## 执行与回退

可以交给 Agent：

> 在当前实例中将会话元数据改为按记录访问。先在真实数据副本上核对完整数据、并发写入和访问耗时，确认全部在线及离线读取入口支持新格式。保留备份，停止旧版本元数据写入者后切换，并验证旧会话、关联、历史及恢复。回退时导出当前最新元数据，不能用旧备份覆盖迁移后的新工作。

只有显式迁移才启用新格式；未迁移的实例继续使用旧数组。写入依赖 Linux `flock`，迁移前核实可用性。每次修改从持有 OS 锁开始读取最新索引，串行完成读取、修改和提交，避免跨进程丢失更新。锁由 OS 在进程崩溃时释放。记录先持久化，最后原子切换索引，多记录事务不会被读到一半。旧读者持有原索引可以继续读取不可变记录。

操作工具为 `node scripts/session-catalog.mjs migrate|verify|export-legacy|prune --file <绝对路径>`。迁移及导出另须 `--offline`；该标志只是确认写入者已停，不会替操作者停服务。迁移前自动保留原数组硬链接备份，比较完整数据后返回条数和备份路径。转换失败不得启动旧版本读取新索引；使用同版本工具导出最新数据，再恢复旧代码。

旧代码不理解索引格式，禁止混用旧写入者。升级时先更新全部调用入口，再停止核心元数据写入进程，转换和验证后重新启动。现有兼容 Request 状态及 detached runner 无需再次转换；不要中断正在进行的业务或重发外部动作。独立观察器、显示端和离线分析工具通过同一格式访问器读取；所有读者必须随源码更新。

核心每小时清理不再引用且超过24小时的记录文件，当前索引引用的文件不会删除。崩溃前写出但未提交的孤立记录也沿此策略清理。旧索引超出保留期遇到文件已回收时，读取方重取当前索引。备份与会话历史不参与清理。一次完整冷列表读取会涉及多个文件，启动成本可能高于单个 JSON；热点单记录读写与全列表操作应分别度量。

## 验证

`tests/test-session-catalog.mjs` 覆盖完整迁移、独立记录读取、多进程累加无丢失、写入进程终止后锁释放、不可变读取快照、批量删除更新、旧格式导出和垃圾回收。`tests/test-work-awareness.mjs --indexed` 验证真实工作目录业务的并发更新及快照共享；普通模式继续覆盖未迁移实例。测试使用隔离临时目录，不向真实群投递。
