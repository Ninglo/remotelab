# 讨论群的参与状态

群顶部的状态卡需要与实际接收、回复和工作行为一致。展示预览不能让群成员误以为已经控制了机器人。

本功能按群显式开启 `participationControls: true`，要求该群已采用 `participationMode: ambient`。未开启的干活群沿用原有机制。状态按机器人、租户、群和话题分别持久化；主讨论与工作话题互不替代。

| 状态 | 普通消息 | 什么时候回应 |
| --- | --- | --- |
| 主动参与 | 继续进入 Session | 按现有上下文自主判断 |
| 旁听 | 继续进入同一 Session，记录为 observation | 只回应 @ 或明确任务命令；回答一次后保持旁听 |
| 暂停接收 | 不进入 Session，不交给模型判断、不下载附件 | 明确恢复接收后，从恢复时点继续；跳过的消息不补读 |

“先旁听”“暂停接收消息”“恢复参与”、`/mute`、`/unmute` 和状态卡按钮可以直接切换。Jev 不再解释自然语言控制、邀请或换话题。旁听时以 @ 或任务命令作单次邀请；纯自然语言邀请不会被小模型自动放行。暂停期间普通内容不交给任何模型；请用明确的恢复命令或按钮。主动参与模式中的是否回复仍由主模型根据上下文判断。

开启此功能后，嘘以及 `/mute` 切换为当前范围的旁听，并请求停止对应 Session 的当前和已排队输入；其他独立工作 Session 不受影响。旧群的嘘和 `/mute` 行为保留。去掉嘘不会恢复参与。

状态先持久化，随后停止当前任务，再更新原共享卡片。卡片按钮和文字修改同一份状态，按钮必须匹配当前卡片及状态版本并通过现有访问策略。卡片显示失败不会放行工作；重试及启动恢复会补更新。旁听或暂停接收时，未获邀请的旧输出会取消投递。恢复接收设置历史读取下界，避免之后的上下文补取读入暂停期间的内容。

已发送且支持共享更新的卡片可以通过 `participationStatusMessageId` 接入。卡片接近 14 天更新期限时，在状态变化或启动恢复时换卡并更新顶部入口；不创建额外定时 watcher。

实现：`connectors/feishu/participation-state.mjs`、现有 `quick-participation.mjs` 与 `scripts/feishu-connector.mjs`。验收：`tests/test-feishu-participation-state.mjs` 及原有 ambient、Jev、响应策略和上下文测试。代码验证、群开启配置、进程重载与卡片读回分别核对。
