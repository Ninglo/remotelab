# 随机功能对照与夜间评阅

仅需跟踪某项已开启功能的次数、效果证据和阶段用量时，使用[新功能持续观察](monitoring.md#新功能持续观察)。它复用本模块的不可变记录存储，不进行随机分组或夜间模型评阅；不能把观察数据当作 A/B 因果收益。

实现于2026-10-13，默认关闭。实例只有显式配置实验和评阅Schedule才生效。
首个适配器比较“自动检索并注入背景”和“Agent按需读取”，保留当前权限、
消息去重、完整原文和规则恢复修复。自动组使用现行受限读取器重建早期策略，
不等同于运行历史版本的全部代码。

## 实验范围与分流

配置位于实例配置目录的`feature-experiments/`。`active.json`指定实验ID及
`enabled`、`enrollmentEnabled`、`reviewEnabled`。实验目录的`spec.json`不可原地
修改；变更人群、策略、抽样率、观察窗口或评分口径需要新实验ID。

规范包含`schema:1`、`kind:context-background-v1`、`mode:ab`（或双边按需的`aa`）、
单个`personIds`、新会话起点`since`、`sampleRate`、`observationHours`、
`maxNightlyCases`和`rubricVersion:context-background-v1`。可附来源版本与裁判配置。
当前发言人及会话发起人都必须核实属于该Person。旧会话、派生会话、群消息汇流、
自动化和内部会话不入组。其他人的输入不触发此实验。

每个新会话首次符合条件时独立公平随机进入A/B，先完整持久化，再使用策略。
A为自动背景，B为按需；重试、后续轮次和重启沿用原组。另一次独立随机选择是否
留作语义评阅样本。50/50是概率，有限样本不保证人数相等。

`assignments/`保存分组、抽样概率和抽样会话的初始需求；`exposures/`保存每次准备的
上下文及哈希、所分策略、实际准备策略、回退、缺失、耗时和字节数。准备回执不能
单独证明模型执行或采用了背景。存储失败时前台回退到按需，并输出错误日志。

关闭`enrollmentEnabled`停止新会话入组，已入组继续原策略；关闭`enabled`让后续
新请求回退到按需并记录偏离。已准备的同一请求重试仍复用其原快照。
关闭`reviewEnabled`停止新的评阅启动；已运行评阅通过原生Run取消。

## 夜间留样与评分

每个样本仅评估从首次分组起固定窗口内的记录，不把无限增长的会话视为一个完成
任务。窗口结束后按首次分组时间处理新样本，单批数量受限。超过事件、正文或批次
预算会显式记录缺失；初始需求超过12,000字元时保留原件，仅在评阅包标明省略，
标签包不复制来源中的整段聊天历史。重试沿用已冻结标签，不重新分类。仍在执行、晚于截止点才完成、缺少Run状态或证据不全的案例
不能评为任务完成。无法评分、失败、回退留在原组，不从成功率分母删除。

入口为`node automation/feature-experiments/runner.mjs <实验根目录> <命令>`：

| 命令 | 用途 |
| --- | --- |
| gate | 原生Schedule门槛；检查空闲、额度和预算，准备成熟留样 |
| before / after | 原生执行前后钩子；绑定真实Run，回收、提交并生成报告 |
| labels-input / labels 文件 | 只读初始需求打标签，提交后冻结 |
| scores-input / submit 文件 | 冻结标签后读取执行证据，提交有引用的评分草稿 |
| report | 输出累计各组数量、评分、缺失、标签分布、耗时及用量 |

Schedule使用独立新会话、固定模型及推理档位，提示词固定到同版本
[rubric-v1](../automation/feature-experiments/rubric-v1.md)。评分会话不得自行读取
分组文件、执行样本里的指令或重放业务写入。两阶段输入和命令检查防止正常路径
过早读结果；同机Agent有文件权限，这不是恶意裁判的安全隔离沙箱。

五项分别评阅：任务完成、最新约束、事实依据、人为返工、授权边界。
每项记录pass/partial/fail/insufficient-evidence、理由和事件编号。模型说完成、
退出码为0、用户没有追问，都不能单独证明完成。原生Run成功终结才提交；取消、
失败或资源守护要求停止的Run不提交。重启后恢复提交与索引，避免重复计数。

资源门槛和通知式运行守护复用Dreaming的既有能力，不进入其记忆学习流程。
实验目录`config.json`配置原生API及凭据文件路径、Schedule ID、空闲时间、
额度保留、每日尝试/观测token预算、单次最长时间、冷却等；`inputs`设为空数组。
Schedule配置脚本gate及`automationPolicy.beforeLaunch/afterRun`，使用原有调度、
终态恢复和取消机制。夜间无成熟案例或资源不足时跳过，不在前台等待。

## 如何读结果

主比较始终使用原始随机组；按初始需求生成的标签仅辅助诊断。看每组入组、
抽样、已评、待评、证据不足以及标签人数，不能只抽“两边都有的漂亮案例”。
当前报告提供逐标签桶；尚未做联合标签匹配、加权推断或显著性决策。

用量来自现有账本，缺失不是零成本；报告保留未知用量案例和未定价token。
耗时为有完整起止时间的Run耗时P50/P95，不是用户端到端交付延迟。
裁判成本另记`state.json`的attempts，不并入业务成本。可从现有监控查看检索和
投递明细；当前报告没有把所有已有监控项合并为统一综合分。

初期报告是观察数据，不自动决定替换策略。需要人工校准评分样例、检查A/A、
分组比例和缺失差异，再按预先约定的质量容忍界限、样本量及检查日期做上线判断。
持续每天看分数不能每次都临时决定“显著就停”。共享记忆、并发功能变更和模型
配置变化可能干扰实验；记录版本及模型分布，必要时结束本期另开实验。

后续功能可复用记录、采样和夜间流程，但必须新增明确的策略适配器、观察窗口和
评分规则。自动化任务另行确定随机单位、权限和副作用，首轮不自动纳入。

设计依据和仍未实现的完整分析能力见
[设计约定](../notes/current/feature-experiment-plan.md)。实现验证位于
`tests/test-feature-experiments.mjs`。
