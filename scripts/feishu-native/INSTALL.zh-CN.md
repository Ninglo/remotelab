# 飞书增强版：一条命令试装

适用于 **M 系列 Mac、飞书 8.1.17**。打开“终端”，粘贴运行：

```bash
curl -fL --retry 5 --retry-all-errors --connect-timeout 15 --max-time 120 https://index.jiujianian.dev/public-pages/feishu-native-install/install.sh -o /tmp/feishu-native-install.sh && /bin/bash /tmp/feishu-native-install.sh
```

命令会检查飞书版本，自动准备所需文件，安装并打开独立增强版。无需手动装 Node、Python、Homebrew 或 Xcode，也无需管理员密码。首次下载约 80 MB，按小片段校验保存；网络失败后重跑会复用完整文件和已完成片段，不再整包从头下载。入口会自动重试网络错误，完整下载后才执行。GitHub 不是必需主下载源。完成后在新窗口登录**你本人的飞书账号**。之后可从个人“应用程序”目录打开“飞书增强版”。

正式飞书和原登录数据保留。重复运行同一命令会保留本次试装的账号、草稿和设置；已核旧版可升级；遇到不支持版本或未完成的旧安装会停止并保留现场，反馈终端提示即可，不要删除原飞书或为试装降级。旧脚本失败时已删除的半包无法恢复，但此前完整下载的 Node 文件仍可直接复用。

## 试用范围与更新

启动器修复版 2 使用同一条命令更新，无需重装飞书或清除数据。它会绕过代理检查本机连接，恢复本安装目录的遗留服务，并在服务连通后打开窗口；不再把连接关闭后的端口等待误报为“其他程序占用”。若确有别的程序占用，保留该程序并报告服务未就绪。

r16 在消息分组侧栏保留 Index、thinking、具身前沿、每日日报，每项标注“（测试）”；最底部固定显示“设置”和实际版本 v16。入口、设置和状态标签跟随当前所选界面字体。侧栏收起或暂未出现时，左下角保留设置入口。Session 状态按 RemoteLab 返回的名称显示，包括空闲；滚动或切换分组不会先清空状态，新订阅收到结果后再切换。真正断线明确显示“未同步”。

Index 是连续私聊，输入框固定在底部；thinking 展示本人参与项目的记忆、相关工作和下一步，待办与日报保留为补充来源。已有分析不会因更新自动重新运行。

主题、字体、设置和消息分组侧栏的四个入口可试。个人 Index、thinking、消息设置、群看板和状态同步共用一次本人连接：从任一连接入口打开同一浏览器页面，登录 RemoteLab 并核对姓名，确认全部功能后自动返回连接完成页。已经有效的完整授权复用；过期、撤销或新增能力时再确认。安装命令不会复制其他机器的账号或连接。该连接也提供已关联话题的用量和已登记消息成果；没有记录时显示未知或不展示。8.1.17 登录后的完整功能、语音输入和会议媒体尚未验收。

本入口用于完整安装和界面代码升级。完整升级时先用 ⌘Q 退出增强版，再运行同一条命令；安装器会校验并备份旧版、保留账号/草稿/设置后升级。兼容的同步服务小补丁可按下节接入自动更新，无需退出或重装。运行中的增强版不会被强制重启。飞书官方升级、增强代码更新和群状态的实时同步是不同功能。

## 停用与问题反馈

退出“飞书原生增强试验”，继续使用原飞书即可。出现错误时，把终端最后一条错误发回原话题；账号、草稿、设置和运行文件留在本机，不必发送整个目录。

维护者核验入口：`bash install.sh --check` 只核对版本与资源。`--source /path/to/Lark.app` 可指定已安装飞书的位置；`--test-home /private/test/directory` 用于隔离验证且不打开应用。安装文件存放在个人 `Library/Application Support/RemoteLab` 下，个人账号数据在独立 `Library/Application Support/RlfeTrial` 下。

## 飞书已读与 review

review 表示 RemoteLab 有尚未读过的结果。r14 支持从飞书同步已读：在设置中重新点“连接状态同步”，统一连接页会明确说明已读同步能力，一次确认同时连接其他增强功能。旧连接仍只读，不会自动获得写入权限。打开话题后，增强版核对原生已读计数、最新消息时间及当前打开的话题，再提交本次看到的结果时间；后台话题、未知结构、断线和较早消息都不会误标。新结果到达仍会重新显示 review；running 和 waiting 仍由 RemoteLab 决定。

只有已核实话题对应关系的行会显示 RemoteLab 标签及标题摘要；普通飞书话题及尚未核实对应关系的话题保持原样。没有标签不等于空闲，也不能据此认定没有关联工作。

增强版使用紫色对话框加号图标，系统显示名为“飞书增强版”，与原版飞书区分。更新保留账号、草稿和设置。首次使用语音输入时，请在 macOS 麦克风权限中允许“飞书增强版”；原版的许可不会自动变成增强版的许可。若列表仍显示旧名称，先重新打开增强版；不要重置所有应用的权限。

## 同步服务小补丁与热更新边界

状态同步服务位于 App 外，兼容 v16 页面协议的小补丁可由维护者远程更新，无需重跑安装器或退出飞书。操作前核对运行中的独立 App、本机服务、旧文件哈希和补丁来源，校验 JavaScript 并备份旧文件；只停止这个安装目录的本机服务，原子替换已核文件，使用原 Node 和能力凭据恢复服务及进程观察器。验收须确认飞书 PID、页面客户端编号保持不变，原页面自动重连、同步恢复，并检查更新前已有草稿仍在；失败恢复备份和原服务。不读取或输出草稿正文，不改变登录或连接凭据。

界面脚本仍打包在签名 App 内，更新它们继续遵循已有退出、备份和签名流程；不能把服务更新成功说成所有增强功能均支持热更新。

同步服务为首次有效状态快照设置 15 秒等待上限：仅收到连接响应或心跳而没有快照时会重试；替换订阅期间保留旧订阅的实时结果。已有连接的 45 秒心跳超时保持不变。这只改善连接建立或订阅切换卡住的情况，不代表正常状态推送延迟已获端到端验收。

## 多台设备接入同一个小补丁更新入口

可以把这句话交给能操作对应 Mac 的 Agent：

> 为这台已安装 v16 的 M 系列 Mac 接入飞书增强版小补丁自动更新。保持飞书运行和现有登录、草稿；核对接入回执与首次检查结果，失败保留现场并报告。

旧版尚未包含更新组件，每台需要首次接入一次；仅在能操作该设备的本机终端运行：

```bash
curl -fSs --proto '=https' --connect-timeout 10 --max-time 60 https://index.jiujianian.dev/public-pages/feishu-native-updates/enable.sh -o /tmp/feishu-enable-updates.sh && /bin/bash /tmp/feishu-enable-updates.sh
```

此命令只安装一个小型更新组件，复用现有 Python 和 Node，不重新下载飞书、修改签名 App、关闭窗口或复制账号。它注册当前用户的 LaunchAgent，接入时和以后每 15 分钟检查一次同一个发布入口；离线时保留当前版本，联网后下一次检查继续。这是**补丁发现周期**，与话题状态的实时同步无关。未接入的设备不会收到更新；不向服务器上传设备列表或账号，所以一台接入成功不能证明另一台也已接入。

下载先验证内置 Ed25519 公钥对应的发布签名，再校验允许更新的文件、旧文件哈希、桥接服务哈希和页面协议。当前仅允许 `topic-source.cjs`、`native-connection.cjs`、`live-source.cjs`；不会接收任意路径或修改 App、启动器、授权文件。只有完全退出或正在健康同步时才应用；服务短暂重连期间窗口保持打开。失败自动恢复备份，并暂停同一失败补丁，等待更高序号修订。中途断电或更新进程被终止时，下次检查先恢复未完成事务，网络不可用也能恢复。

维护者检查本机结果：

```bash
ROOT="$HOME/Library/Application Support/RemoteLab/Feishu Native Trial"
"$(cat "$ROOT/python-path")" "$ROOT/helper-update.py" --status
```

接入命令会等待最多50秒并一起返回 `enrollment` 和 `firstCheck`。`enrolled` 只证明自动检查已注册；`firstCheck` 或 `helper-update-check.json` 中的 `current` 或 `updated` 才证明本次补丁已匹配或应用。`pending` 表示首次结果仍未返回。`deferred` 表示当前页面未连通，稍后重试；`rolled-back`/`held` 表示已回退并暂停失败补丁，须维护者处理。检查结果与备份留在本机，反馈状态即可，不要上传账号文件或整个目录。停用使用同一 Python 执行 `helper-update.py --disable`，保留当前增强版。

发布者使用 `package-helper-update.py --spec <发布规格.json> --key <私有签名密钥> --output <发布目录>` 构建文件哈希对象、签名清单和首次接入脚本。规格包含递增 `serial`、已验证的 `bridgeHashes` 和各文件允许的旧哈希 `files`；私钥独立保存在实例私有配置中，绝不打包或提交。运行隔离的 `tests/test-feishu-helper-update.py` 和对应模块测试，验证真实设备后覆盖同一静态发布入口；保留旧哈希对象供正在下载的设备使用。扩大兼容范围必须先验证，不能放宽旧文件校验来覆盖未知修改。
