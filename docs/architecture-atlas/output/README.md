# RemoteLab 消息与任务输出架构规划

版本：v1 · 2026-10-03。状态：架构规划，尚未整体实施。

源码与实例核对截止 2026-10-03。本页把目标流程与已核对现状分开展示；图中交互是演示，不会创建真实任务、发消息或执行工具。常规部署实例没有据此自动升级。

人类阅读入口：[交互架构网站](index.html)。本目录作为既有架构图谱的“消息与任务输出”专题，沿用其样式和证据边界；不把既有全站视图的旧基线改称最新。

## 目标与职责边界

用户能看到：消息已收到、Agent 是否开始、当前真实进展、是否等待自己、正式结果是否送达。主 Harness 理解任务、规划、调用工具、验收和形成用户内容；RemoteLab 保存请求与事件，负责恢复和跨表面投递。taskId 是 Session 内稳定工作卡的投影身份，不新增全局任务产品。

## 目标图的承接节点

### 网页 · 试验入口

承担者：网页适配器。复用 / 改动状态：已有入口。

人员试验开关影响展示，不改变任务是否真的完成。

- 输入：用户文本、附件、所在 Session。
- 输出 / 下一承接者：HTTP 接纳请求；读取原会话的历史与卡片。
- 持久记录：共享 Session 历史；个人试验配置单独保存。
- 异步与恢复：浏览器断开不停止已接纳工作。重连读最新事实，不重发消息。
- 事实边界：试验卡按 Person / Session 启用；不是端口上所有用户都自动拥有。

源码：`chat/session-manager.mjs`、`chat/requests.mjs`。

### 网页 · 常规入口

承担者：网页适配器。复用 / 改动状态：已有入口。

与试验入口共用接纳和运行底座，展示能力须分别部署与验收。

- 输入：原会话中的一次用户输入。
- 输出 / 下一承接者：规范化 Request 与原会话回复位置。
- 持久记录：Session、Request、Run 和规范化事件。
- 异步与恢复：HTTP 返回接纳回执，不等待模型完成。WebSocket 只通知变化，HTTP 读取事实。
- 事实边界：主线源码、已部署版本和用户收到结果是三种证据。

源码：`chat/session-manager.mjs`、`chat/requests.mjs`。

### 飞书 · 群与话题

承担者：飞书 Connector。复用 / 改动状态：已有入口。

只处理已配置接入范围；无 @ 可被收录，是否承担工作另行判断。

- 输入：真人消息、来源事件、群或话题归属。
- 输出 / 下一承接者：耐久 inbox、规范化输入与原消息绑定。
- 持久记录：消息去重键、发送者、来源和回复目的地。
- 异步与恢复：飞书事件接入、AI 工作、卡片投递独立运行。
- 事实边界：本次核对包含试验分支；普通群的触发配置不同。Bot 消息不当作新真人任务循环触发。

源码：`scripts/feishu-connector.mjs`、`connectors/feishu/session-flow.mjs`。

### 可靠接收与去重

承担者：RemoteLab 接入层。复用 / 改动状态：底座已有。

先可靠记录消息；相同输入沿用身份，不能靠重发制造第二份工作。

- 输入：来源消息标识、用户文本、附件引用。
- 输出 / 下一承接者：接纳回执、Request 身份及 Session 绑定。
- 持久记录：inbox / Request / Session 历史。
- 异步与恢复：接纳成功后不等待模型、清单或飞书发卡。
- 事实边界：目标：表情从这个已确认事件触发。现有 Jev 试验分支的表情仍在快判和提交之后。

源码：`chat/session-manager.mjs`、`chat/requests.mjs`。

### 立即确认收到

承担者：入口确认器。复用 / 改动状态：需前置。

飞书给原消息加表情；网页确认已接收。这里只承诺收到。

- 输入：已经可靠收录的消息。
- 输出 / 下一承接者：收到表情或对应入口的接纳状态。
- 持久记录：确认动作的去重记录与回执。
- 异步与恢复：不等待语义判定，不阻塞 AI 执行。失败可重试确认，不能重提工作。
- 事实边界：表情不能证明模型已理解、已接单或已执行。只收录讨论时可以止于此。

源码：`scripts/feishu-connector.mjs`、`connectors/feishu/session-flow.mjs`。

### 原消息收到状态

承担者：网页 / 飞书原消息。复用 / 改动状态：目标体验。

先看到收到确认；主模型接单后才出现工作开场。

- 输入：可靠接收事实，以及稍后的真实工作判定。
- 输出 / 下一承接者：收到表情 / 接收状态；未判定时不显示已经开工。
- 持久记录：接收回执与工作判定留在原会话。
- 异步与恢复：排队仍显示等待开始。只收录讨论时不生成开工消息或任务卡。
- 事实边界：仅有收到表情不证明 Agent 已接单。工作状态必须来自 Harness 与运行事实。

源码：`scripts/feishu-connector.mjs`、`connectors/feishu/session-flow.mjs`。

### 会话与运行调度

承担者：RemoteLab 核心。复用 / 改动状态：底座已有。

把输入交到正确会话。空闲启动；兼容的运行中输入交给原生通道。

- 输入：Request、Session、选定 Harness 与运行配置。
- 输出 / 下一承接者：启动 Run、追加输入，或明确不兼容 / 需排队。
- 持久记录：请求关联、Run manifest、原生输入接纳记录。
- 异步与恢复：已接纳不等于已消费；不确定的原生投递不能换新 Run 重放。内部维护操作保留串行边界。
- 事实边界：Codex 原生使用 turn/steer；确定无活动 turn 才能退回 turn/start。超时不是确定拒绝。

源码：`chat/native-request-dispatch.mjs`、`chat/native-input-transport.mjs`、`docs/native-harness-input.md`。

### 理解与执行

承担者：所选 Harness。复用 / 改动状态：职责已有。

决定是否接单、工作范围、第一步、长短任务、交付标准与验收。

- 输入：用户输入、上下文、已采用的补充、原生工具能力。
- 输出 / 下一承接者：有信息增量的开场、任务快照、进度、问题、正式结果。
- 持久记录：原生线程与规范化事件；任务事实进入 Session 历史。
- 异步与恢复：原生控制循环处理新输入与工具结果。清单可以稍后形成，执行不等待卡片投递。
- 事实边界：不增加第二个隐藏 planner、回复 reviewer 或卡片生成模型。短任务可以直接给完整结果。

源码：`chat/runner-sidecar.mjs`、`chat/run-launcher.mjs`、`chat/runs.mjs`。

### 工具与外部系统

承担者：Harness 调用的工具。复用 / 改动状态：能力已有。

完成查询、文件修改与外部动作；工具返回后才产生对应证据。

- 输入：当前已采用条件下的工具参数。
- 输出 / 下一承接者：结果、错误与可核对的回执。
- 持久记录：工具事件及对应外部资源。
- 异步与恢复：长调用可以独立运行。新条件不保证改变已启动调用，停止也不能撤销已经发生的外部动作。
- 事实边界：进度由可观察结果支持，不能从工具开始推断工作已经完成。

源码：`chat/runner-sidecar.mjs`、`chat/run-launcher.mjs`、`chat/runs.mjs`。

### 事件与任务记录

承担者：RemoteLab 持久层。复用 / 改动状态：需扩展快照。

保存事实，再从同一份记录生成网页和飞书展示。

- 输入：规范化输出、带证据的验收项、用户输入与送达回执。
- 输出 / 下一承接者：稳定 taskId 的递增快照；可重建当前视图。
- 持久记录：Session 追加事件、workboard 快照与投递记录。
- 异步与恢复：taskId 跨 Run 保持不变；revision 防止旧更新盖住新状态。
- 事实边界：taskId 是 Session 内任务卡的投影身份，不新增全局任务系统。现有 schema 尚无独立 progress / waiting 区。

源码：`lib/workboard-state.mjs`、`connectors/feishu/workboard-pilot.mjs`、`scripts/feishu-workboard-pilot.mjs`。

### 输出投影与投递

承担者：网页投影 / 飞书 Worker。复用 / 改动状态：需统一规则。

开场发一次；普通进度编辑原卡；问题单独卡；正式结果独立发送。

- 输入：带明确输出意图的事件、任务版本和固定目的地。
- 输出 / 下一承接者：表面可读内容、卡片更新及外部回执。
- 持久记录：reply publication / outbox、卡片锚点、分片回执。
- 异步与恢复：慢网络与发卡失败不拖住模型。恢复按最新事实补投递，不重跑任务。
- 事实边界：现有普通进度仍可作为新消息出现；完成态和结果送达已有分别记录的底座。

源码：`lib/reply-deliveries.mjs`、`chat/native-final-publication.mjs`、`docs/external-message-protocol.md`。

### 用户可见结果

承担者：网页 / 飞书表面。复用 / 改动状态：目标体验。

看到是否收到、是否开工、做到哪、是否等自己、结果是否送达。

- 输入：可公开展示的任务投影与正式结果。
- 输出 / 下一承接者：清楚区分进行中、待补充、暂停、完成、失败和取消。
- 持久记录：展示不另造一份任务事实。
- 异步与恢复：离开页面后任务继续；恢复查看同一卡片与结果位置。
- 事实边界：工作完成与答复送达分别显示；停止执行不自动勾完交付项。

源码：`lib/assistant-surface-messages.mjs`、`lib/workboard-state.mjs`。

### 后置整理与归集

承担者：独立后台支路。复用 / 改动状态：已有独立支路。

维护会话标题、工作摘要及有条件的长期记忆归集。

- 输入：已结束轮次的历史和可复用信息。
- 输出 / 下一承接者：Session 元数据及符合条件的归集记录。
- 持久记录：workSummary 与记忆相关记录。
- 异步与恢复：与正式答案投递独立；用户不为元数据整理等待。
- 事实边界：分类器不是任务验收者，不改写答案，也不负责生成这张任务卡。记忆细节见既有记忆架构说明。

源码：`chat/session-turn-completion.mjs`、`notes/current/thin-control-plane-architecture.md`。

## 开场为什么有信息量

仅复述：收到，我会核对试验端口、常规端口和飞书群，先对照源码，进展和结果放在这里。

已有事实与判断：现有链路把执行停止标成“交付”，普通进度又分散在新消息里。我先拆开任务、执行和投递三种状态，确定各入口要改哪里。

主模型基于本轮已有事实，写出具体判断、关键分叉或首步为何能缩小不确定性。没有核实的发现不伪装成事实；快速完整答案直接交付。开场只承担有用增量，接收表情承担即时确认。

## 异步时序

### 长任务

时间线表示先后与独立承接，不表示固定秒数。发卡与投递不会成为模型开工的前置条件。

1. 用户 → 接入 / 调度：消息到达。真人输入进入已配置入口。
2. 接入 / 调度 → 持久事件：可靠记录 + 去重。同一输入只接纳一次。
3. 接入 / 调度 → 用户：收到确认。飞书表情 / 网页已收到；不等模型。
4. 接入 / 调度 → 执行：启动或续接原生运行。返回接纳身份，执行脱离网页连接。
5. 执行 → 持久事件：开场：有依据的判断与第一步。主模型写内容；不套固定寒暄。
6. 持久事件 → 输出 Worker：开场待投递。确定原会话或唯一工作话题。
7. 输出 Worker → 用户：短开场 + 工作位置。开场不等待完整交付清单。
8. 执行 → 持久事件：任务快照 + 继续执行。目标、2–5 交付项；清单只是展示投影。
9. 持久事件 → 输出 Worker：创建或更新原任务卡。保存卡片锚点和任务版本。
10. 执行 → 持久事件：有证据的进度变化。工具返回、关键发现、步骤变化或阻塞。
11. 持久事件 → 输出 Worker：编辑进度区。合并可读增量；不逐句新增消息。
12. 执行 → 持久事件：验收与正式结果提交。证据支持完成程度；不由 Run 终止猜完成。
13. 持久事件 → 输出 Worker：结果进入独立投递。工作已完成，答复待送达。
14. 输出 Worker → 用户：正式结果 / 附件。保留明确结果标识与完成程度。
15. 输出 Worker → 持久事件：提供方确认回执。全部结果部分确认后才显示已送达。

### 快速完整答复

收到确认之后直接完成并交付；不为开场或任务卡制造额外等待。若卡片尚在准备，终态会阻止迟到创建。

1. 用户 → 接入 / 调度：消息到达。原会话接纳输入。
2. 接入 / 调度 → 持久事件：可靠记录与去重。保存来源与回复位置。
3. 接入 / 调度 → 用户：收到确认。不等待模型判断。
4. 接入 / 调度 → 执行：原生执行。主模型形成完整答案。
5. 执行 → 持久事件：正式结果。无需另交清单和开场。
6. 持久事件 → 输出 Worker：独立投递。取消未发出的迟到卡片。
7. 输出 Worker → 用户：完整答案。原位置直接回答。
8. 输出 Worker → 持久事件：送达回执。任务与投递均有可核对状态。

### 缺关键输入

关键问题没有安全默认。完成独立部分后释放当前执行，待答任务与问题持久保留；回复触发同一任务的续作。

1. 用户 → 接入 / 调度：原任务输入。消息已接纳。
2. 接入 / 调度 → 执行：执行现有部分。先完成不依赖用户回答的工作。
3. 执行 → 持久事件：必要问题 + 等待范围。主模型说明缺什么、为什么、阻塞哪项。
4. 持久事件 → 输出 Worker：保存待答问题并投影。问题归属 taskId / questionId / 对象 / 版本。
5. 输出 Worker → 用户：单独交互卡。主卡显示等待补充，已有结果保留。
6. 执行 → 持久事件：结束本次执行，任务仍等待。不自动首选，不维持空转 Run。
7. 用户 → 接入 / 调度：用户稍后回答。可以在断线或本次执行结束后返回。
8. 接入 / 调度 → 持久事件：校验问题与版本。过期问题不直接应用到新要求。
9. 接入 / 调度 → 执行：续接同一任务。新执行消费答案，不是另造任务卡。
10. 执行 → 持久事件：原卡更新 + 继续验收。等待解除，交付项依新证据推进。

### 结果发送失败

工作与交付分开：投递失败只补投递。结果已产生，不再启动模型重复工具和外部动作。

1. 执行 → 持久事件：验证完成 + 结果保存。工作已完成，有可恢复的结果与资产。
2. 持久事件 → 输出 Worker：结果待发送。沿用稳定 publication / 分片身份。
3. 输出 Worker → 持久事件：发送失败或状态不确定。记失败原因；不确定时先读回，不盲目重发。
4. 持久事件 → 输出 Worker：恢复补投递。只重试需要的结果部分，不重跑任务。
5. 输出 Worker → 用户：正式结果送达。用户获得原结果。
6. 输出 Worker → 持久事件：读回并确认回执。全部部分确认，主卡再显示答复已送达。

## 用户反馈与提问

明确停止优先；结构化问题答案核对任务、题号、对象与版本；其他自由文本进入原生会话，由主 Harness 理解。停止不能被当自定义答案。插问直接回答并继续原任务；补充被收录不等于已采用，采用后具体说明变化；纠正标准后重新验收。独立新目标说明旧任务安排。暂停等待明确继续，取消不自行重启。正式交付前的关键纠正先校验，交付后续作保留版本记录。

- **可选偏好**：能不问就说明假设继续；确需询问时明确默认与采用期限。独立工作继续，默认五分钟后用已告知选项。 未回复：系统默认，非用户回答。
- **必要补充**：说明缺什么、影响哪项。受影响部分等待，其他部分继续；独立工作结束后释放本次执行，保留待答任务。 未回复：等待回答；不自动首选。
- **明确确认**：列明动作与影响，只等待必要决定。已有授权的日常工作不重复求确认。 未回复：没有同意就不执行该动作。

当前普通选择题五分钟后默认首项；该现状不满足必要输入与授权的分级目标。必要待答任务可释放本次执行，但持久保留问题；稍后答案续接同一卡片。

## 三种独立状态

- **任务 / 工作卡**：进行中 → 等待补充 / 用户暂停 → 进行中 → 已完成 / 部分完成 / 失败 / 取消。维护者：Harness 给出验收事实，平台保存。同一任务可以跨多个 Run。现有 workboard.status 保留；拟增加 waiting.kind 区分必要输入与用户暂停，不能仅由 Run 终态宣布完成。
- **一次执行 Run**：已接纳 → 运行中 → 执行终态 → 按新输入续接下一次执行。维护者：原生 Harness 与运行宿主。已接纳不等于正在执行；结束本次执行可以留下待答任务。停止确认和任务取消分别记录。
- **结果投递**：尚无正式结果 → 结果待发送 → 发送中 / 失败待恢复 → 回执确认已送达。维护者：publication / outbox Worker。工作完成不等于答复送达。发卡、答案、附件和分片须有各自回执；不确定发送先读回。

## 交接契约（规划名称，非现行 API）

- `message.received`：接入层 写入 消息已可靠记录与去重；接收确认器 / 会话调度 消费。事件名为规划，不是现行 API。
- `input.accepted / input.applied`：原生桥接 / Harness 写入 通道已接纳 / 主模型已采用，分别记录；运行观测 / 进度区 消费。已有接纳底座；采用展示待补。
- `assistant.opening`：主 Harness 写入 有信息增量的判断、第一步与输出归属；开场投影 / 工作话题入口 消费。内容职责与合并规则待落地。
- `task.snapshot`：Harness 提交；平台结构校验 写入 taskId、revision、goal、items、progress、waiting；Web / 飞书原卡投影 消费。拟扩展现有 workboard 快照。
- `question.opened / answered`：Harness 定义；问题 Broker 存储 写入 questionId、等级、对象、任务版本、未答政策及回答来源；交互卡 / 当前或下一次原生执行 消费。分级与持久待答待补。
- `result.committed / delivery.confirmed`：Harness 验收 / 投递 Worker 写入 正式结果与完成程度 / 提供方确认的回执；结果消息 / 卡片答复状态 消费。复用现有出版与投递底座。

## 改动与真实入口验收

### 接收与开场

承担者：接入层 + Harness + 输出适配器。

现状：Jev 试验分支先快判再提交，表情排在之后；另有创建会话的入口通知。

改动：可靠收录后前置确认；主模型给有依据的开场；群内开场同时作为唯一工作话题入口。

验收：无 @ 的接入消息能确认收到；未接单不假报开工；快速答案不会被迟到开场和卡片打断。

### 一张任务卡承载进度

承担者：Harness 写事实；持久层与 Web / 飞书投影。

现状：卡片有目标、验收项和总体状态；普通进度仍走可见文本，缺独立进度区。

改动：扩展 progress 与 waiting；标题用目标；按真实变化更新原卡，保留必要历史。

验收：同一 taskId 跨 Run 仍是一张卡；普通进度不产生新消息；重连恢复最新版本，不重发旧历史。

### 分级问题与续作

承担者：Harness 定等级；问题 Broker 保存与路由。

现状：普通有选项提问五分钟后默认首项；必要性没有单独字段，表面仍是问题文字。

改动：交互卡注明级别、未答政策、影响范围与对象；必要问题持久待答，不超时强选。

验收：必要补充无回复保持等待；可选题的默认标记非用户回答；跨 Run 的迟到答案正确接回原任务。

### 停止、插问、补充与纠正

承担者：原生输入通道 + Harness + 结构化控制。

现状：已有原生追加输入和停止底座；存在待答问题时把新文字作为候选答案的路径。

改动：停止控制优先，答案绑定具体问题；自由文本交给 Harness 分类处理，实际采用后写进度。

验收：待答时说停止不被吞成答案；插问不结束任务；纠正影响的标准重新验收，收到与采用可区分。

### 完成与送达分别展示

承担者：Harness 验收 + publication / outbox Worker。

现状：已有独立投递与回执底座；现行文本标签主要取决于执行是否停止。

改动：明确正式结果输出意图和完成程度；卡片同步工作状态与答复状态，竞态中阻止迟到创建与过期结论。

验收：Run 结束不自动宣布成功；发送失败只补投递；结果前有新纠正先校验，结果后续作有修订记录。

## 不变边界

- 接收确认不等待模型；收到不冒充已理解或已开工。
- 主 Harness 是唯一任务理解与验收者；不增加隐藏 planner 或独立卡片模型。
- 同一任务在 Session 中保留稳定身份；Task 卡是投影，不另造全局任务产品。
- 普通自动进度更新原卡；用户主动提问仍直接得到回答。
- 必要输入与真实授权不会因无人回答而默认同意。
- Run 结束、任务完成、结果送达分别有证据；互不替代。
- 原生输入或外部发送结果不确定时先核对，不靠重复执行消除不确定。
