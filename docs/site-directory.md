# 项目总站

把下面这段交给 Agent：

> 打开当前实例的 `/sites` 项目总站，收整已经发布的网站与资源。复用真实发布记录，补充有依据的项目、负责人、源码或部署位置，以及身份方式、账号映射状态和埋点接入状态；在备注中保留核查依据、范围与时间，未知项保留待确认。新站自动入册，其他实例、外部网站和 RemoteLab 根入口手工登记。保留原访问权限，不执行删除或迁移。

总站沿用自有飞书员工登录，同一浏览器在已接入的员工网站之间复用会话。公司 SSO 当前未启用。页面和目录 API 都需要员工身份，不授予 RemoteLab 控制台权限。

## 自动收录与补充登记

| 内容 | 来源与更新方式 |
| --- | --- |
| 静态网站、安装包和其他资源 | 每次打开目录读取当前 `public-pages` 下的真实发布记录；HTML 名称来自页面标题，非 HTML 单列为资源 |
| 动态网站 | 读取当前 `preview-routes.json`，保留已有员工登录或 Basic Auth 策略 |
| 外部网站、其他实例 | 员工填写名称、链接与维护信息；登记不修改外部网站，也不代表已迁入当前实例 |
| 项目、维护联系人、说明与备注 | 员工可在总站补充，保存修改人、时间、版本与历史；创建人取真实发布记录，不能被登记表覆盖 |
| 身份方式、账号映射与埋点状态 | 按核查结果补充，列表展示，支持筛选与导出；旧记录默认待确认，不从访问策略自动推断 |
| 原始来源 | 后续静态发布自动把发布输入目录存入私有记录；动态入口记录发布工作目录和服务端口，工作目录不等于服务源码位置 |

历史记录缺少创建人、项目或源码信息时显示“待补充”，不按目录名称或操作系统用户猜人。
“在用／筹备中／已归档”是人工整理状态，不是实时健康检查。目录中的条目不保证网站在线。
已经补过登记而后移除的托管入口仍保留说明，标为入口已移除；归档操作只改变目录标记，不停止服务。

默认覆盖当前实例，不能据此宣称已收齐公司所有机器的发布内容。外部登记会记录当前登录员工为登记创建人；可另填原网站维护联系人。

## 身份、映射与埋点登记

三个字段是登记信息，保存它们不会开启登录、关联账号或发送行为事件。`access` 仍来自原发布记录，与补充的身份方式分别保留；例如公开页面内也可能另有业务登录。

| 字段 | 可登记的值（JSON 值 → 界面含义） |
| --- | --- |
| `identityMethod` | `unknown` → 待确认；`public` → 无需登录；`feishu` → 飞书员工身份；`remotelab` → RemoteLab 账号；`site_account` → 站点独立账号；`basic` → HTTP Basic Auth；`mixed` → 多种身份方式；`external` → 外部身份服务 |
| `accountMappingStatus` | `unknown` → 待确认；`not_required` → 无需映射；`pending` → 待映射；`partial` → 部分已映射；`mapped` → 已映射；`blocked` → 映射受阻 |
| `telemetryStatus` | `unknown` → 待确认；`not_connected` → 未接入；`planned` → 待接入；`connected` → 已接入待验收；`verified` → 已验收；`blocked` → 接入受阻；`not_applicable` → 不适用 |

“已映射”应对应明确的账号范围；“已接入待验收”表示已完成接线，“已验收”还需实际事件和归属回读。核查依据、账号覆盖范围、事件来源与验收时间写在现有维护备注中，不填写身份令牌或凭据。任一字段为待确认时，条目计入待补充；待映射、部分已映射或待接入可通过相应状态筛选。

## RemoteLab 根入口如何登记

根路径 `/` 是控制台自身，既不是静态发布，也不是动态预览，不会自动入册。使用“登记外部网站”登记当前实例的正式 HTTPS 根链接即可；这里的“外部”表示不由发布目录自动收录，同域入口也可登记。兼容域名记在备注中，避免把同一服务重复登记。其他实例仍分别登记。

创建请求为 `POST /api/sites/entries`，内容 `{ "revision": 0, "values": { "title": "RemoteLab", "url": "https://example.test/", "identityMethod": "remotelab", "accountMappingStatus": "unknown", "telemetryStatus": "unknown" } }`，实际提交须沿正常员工会话和同源规则。先查列表是否已有该正式链接；已存在则以原 `id` 与最新 `revision` 局部 PATCH，保留原创建人、备注和讨论。只提供候选登记数据时不调用写接口。

登记创建人是本次提交的员工，不代表 RemoteLab 服务的原创建人。原创建人未核实就保持未知，在备注说明；不能将控制台管理员或维护人代填为原创建人。根入口的登录兼容、飞书映射和行为采集沿控制台各自的实现与验收，不因总站中有登记而改变访问权限。

## 后续维护与迁移

搜索名称、项目、创建人、维护联系人、链接或身份与接入状态，按项目、网站类型、缺失字段及三项新增状态筛选。
“导出迁移清单”下载带版本和生成时间的 JSON，包括访问入口、原访问方式、创建人、联系人、项目、发布目录或端口、已有来源、备注，以及三项身份与接入字段。列表和导出使用同一数据源；`registrationOptions` 提供字段的枚举值与中文含义。JSON schema 保持版本 1，新增字段为兼容扩展，旧读取方可忽略它们。
它不包含密码、访问 Token、Cookie 或应用密钥，也不打包网站文件；实际迁移仍需补齐代码仓库、数据、运行依赖和凭据交接。

静态条目优先使用当前实例的有效托管路径，原发布链接另存以辅助域名迁移。新发布输入可能是临时构建产物，应在登记中另补稳定源码仓库和构建方法。
其他实例不会被本页自动访问或抓取；填入链接不触发后端网络请求。

## 存储和安全边界

- 页面 `/sites`，列表 `GET /api/sites`，导出 `GET /api/sites/export`；均经共享员工身份检查。
- `POST /api/sites/entries` 登记外部网站，`PATCH /api/sites/entries` 补充已有记录；同源提交、版本冲突检查，防止覆盖同时编辑。
- `site-directory.json` 保存补充信息与修改历史；`site-origins/` 保存按发布标识关联的私有来源。两者位于实例 config 目录，0600 写入，迁移和备份时一起保留。
- 旧登记不需要批量改写；缺少的新增字段在读取时补为 `unknown`。局部保存只更新提交字段，保留原备注、创建信息、历史及已有额外数据；非法枚举被拒绝，版本冲突须刷新后处理。
- 原 `_remote_publish.json`、预览入口和网站访问权限不被表单修改；完整源码路径不会写进公开发布元数据。
- 网站登录只负责员工身份；总站提供共享的低风险登记编辑，不新增业务网站权限管理或管理员控制台。
- 链接限制为 HTTP(S)，拒绝 URL 内账号密码和明显授权参数；界面按文本呈现登记内容。员工不应在备注中填密码或密钥。

## 验证

`node scripts/run-with-clean-instance-env.mjs node tests/test-site-directory.mjs`
覆盖自动收录、私有来源、旧记录兼容、创建人/权限/评论与关联保留、新字段校验与持久化、根入口登记、重复链接、并发修改冲突、导出和匿名访问。
设置 `SITE_TEST_PLAYWRIGHT` 与 `SITE_TEST_CHROME` 可验证搜索、三项状态筛选与编辑、外部登记、文本注入防护和手机布局；测试登录是隔离 fixture。
发布器、动态代理和员工登录仍运行各自的回归测试。生产验收另核实际目录数量、来源、匿名拒绝和加载版本。
