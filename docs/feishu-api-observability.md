# 飞书 API 调用追踪

连接器与进展卡片写入器的 SDK 请求在本实例配置目录的
`feishu-api-logs/` 记录结果，每次实际发出的请求只记录一次。字段包括
UTC 时间、应用、来源 Bot、组件、HTTP 方法、脱敏接口路径、耗时、结果、
飞书错误码和诊断编号。SDK 隐藏成功响应的 HTTP 状态时该字段为 null。
令牌请求也记录接口和结果；请求头、请求体、响应正文、查询参数和资源 ID
均不保存。文件权限 600，目录权限 700；按 UTC 日期分文件，16 MB 分段，
保留 31 天。写入失败或队列过载会告警，继续处理原 API 请求。

查询最近七天的应用和接口排名：

```bash
node "$REMOTELAB_PROJECT_ROOT/scripts/feishu-api-usage.mjs" --days 7
```

这是本实例观察到的请求数，不是飞书组织计费总量：直接运行的 `lark-cli`、
未升级的其他实例、进程异常退出时未写完的请求均不保证覆盖；日志也不判断
某个接口是否计入飞书额度。历史用量不补造。

文档读取只由实际收到的评论事件触发，最多两篇同时处理。启动、重连及新绑定
不再自动补漏；旧版本积压的自动扫描任务只在本地归档，不发出 API 请求。
评论分页和回复读取共用至少 400 毫秒的请求间隔；限频后全队列暂停至少五秒，
并提高后续间隔（最多四秒），同时尊重 Retry-After，避免快速响应导致请求过密。
已收到但未完成的评论事件跨重启保留，继续进入原绑定会话。
事件触发的文档读取暂时失败最多尝试五次，逐次退避，并尊重
Retry-After；已识别的永久权限、资源或绑定错误保留失败回执并停止自动重试。
未知业务错误使用同一有限重试预算，避免把暂时服务故障误判为永久失效。
修复权限后核对原错误和新证据，再清除对应文档 `.state.json` 中的
`retryBlocked` 和 `retryBlockedCode`，等待后续评论事件；绑定变化仍走显式重绑定。
无变化的卡片只推进本地序号，不再发出相同更新和读回。
