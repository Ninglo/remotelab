# 飞书 Web 话题状态同步

Mac 原生版的消息列表只替换话题标题并显示运行状态，第二行使用飞书原来的最新消息预览。服务端对已授权的本机来源返回空摘要，现有 v14 会还原被隐藏的原生预览；网页列表及群看板仍保留各自的摘要。状态流先发送实时状态，再异步补充用量、额度和成果，附加信息读取缓慢或失败不应阻塞运行标签；较晚返回的附加信息不能覆盖更新后的状态。

可把以下内容交给维护实例和插件的 Agent：

```text
请发布飞书 Web 1.2，给普通插件接入已验证话题的 running、waiting、review、
标题和摘要。使用 RemoteLab Web 的原状态模型和真实执行状态；不能从任务清单
完成或旧快照推断当前 running。插件内常驻显示实际加载版本，Mac 后续更新
在后台准备文件并由扩展自动应用，保留原生消息和输入。先验证账号、只读范围、
断线、运行结束、文件更新失败与编辑中延后应用，再核对最新线上和离线包。
首次账号连接由本人登录、核对姓名并确认，不借用实例所有者或联调身份。
```

插件的状态通道独立于个人 Index/thinking 和消息设置。`topics` 连接默认只允许
读取当前列表请求的、已核实对应的 Bot-2 群话题标题、摘要、状态和 Session 链接；
私聊、其他来源、未验证或冲突对应不输出。当前实例仍按既有规则允许已认证成员
查看共享 Session，连接不是新增 Session 权限隔离。旧设置和 workspace 凭据
不能进入该通道，旧授权不会自动扩权。

首次打开飞书时，插件直接显示启用引导，连接一次本人账号并核对姓名。
已在同一飞书来源和原生账号下连接 Index/thinking 的浏览器自动复用该身份，
换取独立只读话题令牌，过期时间不超过原连接；无需再去设置启用。
连接 30 天有效，绑定 Person、当前飞书来源和浏览器账号；服务器只保存
`fwtops_…` 的哈希。切换账号立即清除之前的显示和连接，断线显示“未同步”，
不继续把旧 running 当成当前状态。review 的可见性读取飞书原生预览的
`unreadCount`，已读后隐藏，新未读结果再次显示；不把点击话题猜成已读，
也不修改共享 RemoteLab Session 的审阅状态。running 不被阅读动作清除。

- `GET /page/feishu-web-topics/connect`：本人连接页。
- `POST /api/feishu-web-topics/grant`：同源且明确确认的本人连接。
- `POST /api/feishu-web-topics/activate`：用已确认的同账号 `fwspace_…` 连接启用只读状态；不能用消息设置、话题或服务令牌。
- `GET /api/feishu-web-topics/snapshot?ids=…&groups=…`：最多 200 个原生列表编号，及当前原生群编号。
- `GET /api/feishu-web-topics/stream?ids=…`：同一范围的服务端事件流。
- `DELETE /api/feishu-web-topics/connection`：撤销当前连接。

请求带 `Authorization: Bearer fwtops_…`、`X-Feishu-Origin`、
`X-Feishu-Account`；读取和推送仍只接受话题令牌，普通服务令牌和其他插件连接不能代用。状态推送沿原
Session 变更通知，单项变化只刷新对应会话，列表或验证对应变化才重新映射。
每 15 秒传输心跳并重验连接；撤销或过期会结束事件流。浏览器 45 秒未收心跳
标记失效，重连在 120 秒期限内退避；耗尽后等焦点、网络或账号变化重新启动。

实例配置 `CONFIG_DIR/feishu-web-topics.json`：`version: 1` 和绝对路径
`bindingsFile`。文件引用现有、已核实的 API 首帖 → 原生列表编号索引；不复制
项目主账，不按群名、标题或浏览器传入的 Session 编号猜对应。配置仅由维护者
注册，接口不接受任意路径。可选 `groupsFile` 和 `boardPairsFile` 引用原有
已核群编号索引和配对配置；只有两边群编号都核实且浏览器当前群匹配时，
才返回该配对的群汇总。汇总沿原 Mini 模型和当前 Session 来源，排除私聊、
其他连接器路由及无关群；不新增业务账本或模型分析。只读取受限大小索引，不向公开安装包打入聊天快照
或凭据。首次安装与索引发现的原流程分别维护。

Mac 完整安装器注册用户级 `dev.remotelab.feishu-web-updater` LaunchAgent，
每 5 分钟检查原最新发布记录。相同版本只读取小记录；更高版本完整下载并按
固定 SHA-256 校验后替换已识别目录。网络失败、未确认记录、未知目录、较高
本机版本或校验失败都保留现有安装。扩展每分钟检查自己本地 manifest；确认
更高本地版本后等待设置关闭和个人输入保存，再重新加载已安装扩展并注入当前
飞书页，不重载原生页面。不执行远程下载的 JavaScript。Linux/Windows 的
文件准备仍走手动更新，状态通道同样持续推送。

停用 Mac 文件后台更新可交给 Agent 执行：卸载上述用户 LaunchAgent，并删除
对应 plist；不删除插件、浏览器设置或其他服务。离线包包含当前完整安装器，
不需要首次再从分发域名下载安装文件。后续自动更新依赖发布入口连通；网络
恢复后下轮检查继续，不把更新检查失败说成安装失败。

代码、接口、安装器、独立浏览器和本人真实使用分别核对。不能以 Mini 联调
窗口成功替代普通扩展验证；本人 MacBook 的最后一次安装和首次连接仍由其
现场操作确认。

原生浏览器桥接只提供账号、当前群/话题编号和未读数，以及用户点击后的固定原生话题导航。没有任意执行代码、远程脚本或消息发送入口。

## 独立 Mac 原生客户端

M 系列、飞书 8.1.17 的原生增强 r10 使用同一只读本人连接；本机服务聚合列表与聊天页的真实编号，直接订阅群看板和 Session 状态，不依赖 Mini 浏览器。旧 Mini 的同账号来源保持独立。

新原生连接页明确展示扩展读取范围，确认后保存 topicDetails 标志；旧话题令牌及 workspace 自动激活不会自动扩大范围。带该标志的状态结果同时提供已关联话题的累计用量、最近上下文用量和额度显示字段；复用原用量账本缓存，不返回账号信息或消息正文。初次上下文查找最多回看 4096 个事件元数据，未找到时显示未知；后续按序号增量读取。额度与用量每分钟刷新，状态仍沿 Session 通知。可选配置 artifactsFile 指向现有 schema-1 网页成果登记文件，只返回 Session、群、首帖均匹配且源码哈希有效的成果。没有成果或来源读取失败不会伪造内容。

一条命令支持首次安装、已核旧版升级和重复运行。升级前退出增强版；安装器先验证新副本签名，再替换应用，保留账号目录、草稿、偏好和旧版回退文件。导航采用 64px 紧凑布局，原生最外层导航仍保留。入口与版本范围见 scripts/feishu-native/INSTALL.zh-CN.md。

## Mac 原生 r13 已读同步

原生增强在本人连接页明确确认 `topicReadAck` 后，可调用 `POST /api/feishu-web-topics/review`，提交已核话题编号 `webThreadId` 和实际看到的结果时间 `resultAt`。旧令牌及 workspace 自动换取的令牌不包含此能力，需本人重新连接。原生端先核对当前打开的话题、原生 `unreadCount=0` 及最新消息时间，未知结构不猜测。服务器重新验证话题对应，在元数据锁内只推进 `lastReviewedAt`，不标记晚于该回执的新结果；沿现有失效通知同步各端。该字段沿用 RemoteLab 的共享审阅语义，不新建个人审阅账本。网页插件原有的本地隐藏逻辑不变。

r13 消息分组侧栏的四个功能分别标注“（测试）”，底部固定“设置 + 实际版本”；设置、入口及状态标签共用界面字体。详见 [原生安装和验证范围](../scripts/feishu-native/INSTALL.zh-CN.md)。

## Mac 原生 r14 统一连接

统一连接页一次确认并原子签发 settings、workspace、topics 三个独立范围的令牌，明确包含已读同步；浏览器同页返回固定本机地址，回执置于 fragment 并立即清除，不进入服务器请求 URL。每项仍绑定本人、当前飞书账号、固定来源和有效期。客户端完整校验后一次保存，已有有效完整连接复用。群看板除群页头编号外，也可沿请求中已核实的话题编号取得所属群；未知编号和私聊不推断群归属。原生显示仍需在使用者机器上验收。

## 新话题识别不依赖联调电脑

原生客户端已经发送当前列表编号。服务端可选配置 `nativeNamespacesFile`，指向实例内维护者登记的 `version:1` 编号规则文件；不会从客户端提交的数据学习规则。每项 profile 限定 `route`、`tenantKey`、`appId`，指定 `encoding:thread-xor64-v1` 和十进制 `mask`，附带至少 16 条、来自至少 3 个群的独立核实样本（`rootId/chatId/threadId/nativeId/createdSeconds/position`）。全部样本必须满足同一 64 位变换、原生编号时间字段及唯一性；重复命名空间、矛盾样本均不启用。

这是对当前已核实编号命名空间的版本化适配，不是飞书公开承诺的跨应用编码标准。新话题只有同时匹配已登记应用/租户，以及连接器保存的原始首帖身份、群、话题编号和创建时间时才参与投影。私聊、回复冒充首帖、不同应用/租户、缺原始记录、时间不符及冲突对应均不猜测。变换结果只在本次请求内使用，不污染历史已核实绑定。已有绑定和授权范围保留；此修复不需要客户端重新安装或扩大个人授权。新的 Session 失效通知会重新检查此前尚无对应的可见话题。

首帖时间检查允许消息与话题分配同秒，或晚一秒：已独立绑定的历史首帖中，两种情况均有实证。消息早于话题或晚两秒及以上仍拒绝；原始信封和接收记录的消息时间必须完全相等，不放宽应用、租户、群、首帖及话题身份检查。

维护者应把已核实的绑定、群索引与命名空间规则放在本实例配置目录，保存迁移前副本。上线验证须关闭所有 Mini 来源，使用空旧绑定和真实新首帖，验证新话题、状态变化、已读同步及冲突拒绝。客户端实机显示仍需独立验收；不能把样本检验替代新的编码版本兼容验证。

## 状态变化的传输延迟

状态开始、结束和已读变化仍由 Session 通知立即触发，不等一分钟兜底刷新。
连续通知合并保留全部变更编号，无关话题不再重读整组会话；新话题、删除和绑定
撤销仍检查当前成员。状态查询跳过连接器展示与投递问题扫描，但保留同一运行、
排队、待答问题和已读状态模型。只变动活动时间戳时不重复发送整份群看板。
用量等附加信息最多每五秒刷新一次，不阻塞运行状态。

兼容的原生 helper 可用 `stream?ids=…&delta=1` 接收增量协议：每次连接先收完整
快照，随后接收带基准序号和新序号的字段变更。helper 还原完整数据交给原界面；
序号不连续、路径无效或断线后重新连接并取得完整快照。未启用增量的旧客户端
继续接收完整快照。实现见 `chat/feishu-topic-stream.mjs` 与
`scripts/feishu-native/topic-source.cjs`；兼容 helper 可沿已接入的小补丁渠道更新。
测速需区分服务器生成、网络收到与界面显示，不能把更新成功当成状态提速验收。

原生 helper 的状态连接会读取 macOS 已启用的 HTTPS 代理；启用时沿该代理建立
经 TLS 校验的长连接，没有配置时保持直连。不会更改系统代理，代理失败也不会
悄悄改成直连。这样避免安装器下载已走系统代理，而日常状态同步仍走不稳定直连
的差异。首次快照和后续增量需分别测速；测速期间服务重启的样本单独记录。
