# Codex account and quota status

Settings → Codex login now shows the current account's display name (when supplied), email and plan. API-key sign-in is labelled explicitly. Quota loads independently so a slow usage endpoint does not delay identity or the login controls. Identity reads have a 12-second deadline; remote quota reads allow up to 45 seconds (live transport can exceed 25 seconds). Each supplied quota bucket shows remaining percentage, its actual window duration and reset time, plus the observation time. Unknown windows do not become zero; elapsed reset times request a refresh rather than implying a renewed balance.

The only Codex RPCs are `initialize`, `initialized`, `account/read` with `refreshToken: false`, and `account/rateLimits/read`. No thread, turn, prompt, model, AI session, scraping, or usage estimation is involved. Protocol reference: https://learn.chatgpt.com/docs/app-server#auth-endpoints . Codex remains the authentication and token-refresh authority; RemoteLab never refreshes grants itself.

`lib/codex-account-status.mjs` implements a bounded stdio exchange with the installed CLI and the same resolved Codex home as the instance. It returns an allowlist of public fields. A local ID-token name is display-only and only joins a matching RPC email. Tokens and raw provider errors are never returned. A credential revision prevents combining a query with a login changed while it was in flight; the UI also discards earlier request generations and mismatched account revisions. Missing names remain missing.

The existing authenticated `/api/codex-auth/status` adds `account` and an opaque `accountRevision`. `/api/codex-auth/rate-limits` returns `codexUsage` independently. Both are private/no-store HTTP responses. Usage has a process-local 60-second cache bound to the resolved home and credential revision, concurrent requests share one query, and explicit Check status requests bypass the cache. Keyring-backed accounts without a local revision are not cached. Logout invalidates cached usage. Missing/failed usage is visible and retryable; API-key or other non-ChatGPT auth reports that subscription limits are unsupported.

Validation: `test-codex-account-status.mjs` exercises safe projections, multiple buckets, missing fields, exhausted windows, changed accounts, mismatched local names, errors, timeouts, cache invalidation, single-flight reads, logout and owner authorization. `test-codex-account-settings-ui.mjs` executes the UI in a VM to verify literal identity text, both languages, quota formatting and stale-request rejection. Existing device-login/logout and account-switch tests remain in the merge-safety suite. Installed-CLI checks use only the read-only methods above.

## Saved accounts and background default selection

Settings → Connections → Codex lists saved accounts. Adding an account starts an independent device login and keeps existing accounts signed in. Selecting a saved account changes the default for subsequent requests; a running turn retains its selected account. Explicit logout applies only to the selected account and is refused while that authorization is in use. API endpoints add `GET /api/codex-auth/accounts`, `POST /api/codex-auth/accounts/policy` with a boolean `autoSwitch`, and an optional `accountId` for selection or reauthorization. No endpoint accepts credential material or filesystem paths.

The instance-local `config/codex-accounts/accounts.json` stores the list and policy. The original Codex home is the default slot. New account homes hold separate, continuously refreshed credentials while sharing local conversation files and instructions. Switching never copies or restores credentials. The policy defaults off until enabled for that instance.

Foreground requests read the saved default and start normally: no quota RPC, account queue, availability scan, or automatic task replay. Same-account requests can execute concurrently as before the account list was added. Each run has an independent local liveness record so idle monitoring and explicit login/logout can check whether that home is in use. These records do not allocate or serialize execution capacity.

With automatic switching enabled, a lightweight instance monitor runs in the background every 30 seconds, skips active authorizations and reuses recent samples. Native turns also report quota through their existing App Server. Fresh quota at or below 10% selects a different subscription with fresh quota above 10% for later requests. The running task keeps the original account and its remaining reserve. Unknown/stale quota or network/authentication errors never cause switching. If no suitable backup exists, the default remains unchanged; a reserve reduces exhaustion risk but cannot guarantee that a long task finishes within it. A confirmed subscription-exhaustion failure updates the next default without restarting the failed run.

`scripts/codex-account-observe.mjs` shares this cache with the optional local fleet adapter; fleet monitoring is not required for switching. Idle quota reads, device login and logout still use short control ownership to avoid competing credential maintenance. Imported monitor homes remain in place and their previous collectors must be marked externally managed before runtime use. External CLI jobs using the same home do not automatically register their liveness. Background classification supplies large Codex prompts on stdin and releases its liveness in a `finally` block, including process-launch failure.

Validation covers a 10% reserve, background-only selection, no foreground quota RPCs, concurrent same-account startup while a monitor holds its control lock, ongoing-run isolation, independent login and persistence, stale/unknown quota, duplicate subscription identities, and batch/native saved-thread continuation on the next request. An exhausted run executes no automatic second attempt, so previously completed actions cannot be repeated by account rotation. Real-account cross-home continuation was separately verified with the installed CLI and native App Server.
