# 开工检查 v2

仅适用于本次已核工作发起人及已接受工作。检查用于理解已有能力和接续当前工作；按需要补证，不为检查另加一轮固定流程。简单问答直接答，明确接续只查有变化的部分。

- 先结合本轮原消息、已接受上下文和当前话题理解目标。利用本轮已经提供的项目背景、工作目录、身份、规则及原讨论；这些内容可能由服务增量替换、去重或压缩恢复。没有某一块时保留未知，不假设每轮都带齐，也不因历史里看过就认为它仍是当前版本。
- 先指出真正缺少什么，再选择查询入口。当前材料已足够时直接推进；缺少已有工作线索时用 `remotelab work context --query <理解后的具体目标或能力/操作对象> --focus work --json`，有确切路径或业务ID时加 `--object`。先用已有目录和明确项目线索缩小范围；项目归属已核实或要查指定项目参考时可加 `--project`，它不自动绑定项目。
- 缺少项目背景或适用规则时，用 `remotelab work context --query <目标> --focus project --project <已登记ID> --json`，或沿现有项目原件指针读取。只有确需公司、人物或跨项目背景时才补相应来源，不固定重读全部背景。普通完整视图仍可用，但不把查询成功当作已理解。
- 按目标对象、已有入口、实际能力与处理方式找复用点，不只搜同名词。先看候选的目标、最新结果、来源、时间和状态，读真正可能影响当前工作的原件。候选不足或问题明显涉及其他项目时再扩展检索；同一未变目标不反复执行同样查询。查不到只说明所查范围，不认定没有已有功能。
- 在提出方案或修改实现前，确认已有能力能完成哪部分、当前缺什么、这次改动影响哪里。归档、已完成、停止的工作可以提供参考，不代表应恢复执行；空闲和近期标签不等于业务仍在做。必要时从最新配置、代码、产物和原决定补查，不能用标题或旧摘要替代。
- 新工作用 `work start` 登记、实际结果用 `work update` 更新，同一事项接续不重复建账。保留有用来源和读取证据，相关性结论可用 `work review` 记录，空结果也有效。不扫所有邻近话题，不另开分类器或后台复核任务。
- 保留当前话题与既有授权。关键归属或影响不清时只问具体缺项，同时继续独立工作；个人开关不扩大跨群权限。补充问题单独答清，原工作继续。检查不要求逐项汇报、开场或额外清单。

规则随本人配置应用于后续新工作；已接受工作保留原版本与授权，不追溯替换历史快照。
