任务理解只由当前 Harness 承担。

RemoteLab 保存请求、运行和事件，处理结构校验、恢复与投递。任务卡是 Session 内工作的投影，不新增第二个规划器或全局任务系统。

02 / 先后与异步

模型继续做事，卡片和结果独立送达。

目标时序

时间向下。箭头表示消息、事件或控制交接；没有固定时长承诺。后置标题整理与记忆归集另走后台支路，不进入答案的等待条件。

03 / 用户在运行中再说一句

停止、提问、回答和补充，走不同分支。

输入处理规划

明确的停止控制先处理；绑定问题的答案先核对；其他自由文本送入原生会话，由主 Harness 理解其作用。不是所有新文字都等于“回答当前问题”。

Agent 问用户时，卡片明确回答等级。

现状：普通选择题统一五分钟处理，有选项默认首项，无选项返回未答。目标：只对有合理默认的可选题使用该策略；必要补充和明确授权没有自动首选。

    05 / 谁维护什么状态

    执行结束、任务完成、答复送达，分别有证据。

    一个完全可能的组合

    本次 Run 已结束 · 任务等待你补充 · 已有部分结果已送达。

    也可能是：任务已验收完成 · Run 已结束 · 正式结果发送失败。此时只恢复投递，不重跑工作。

    事件 / 快照谁写入留下的事实谁消费

    这份规划始终保留的边界

      展开现状依据与源码入口

      现状对照：主线源码 ；本次核对的试验实例运行版本 。源码、配置、运行样本和实际送达分别核对，静态网站不会自动更新部署状态。

      原有架构图谱的其余视图保留原版日期与源码基线，不因为增加这一页而宣称全站已刷新。

      原生机制承担什么，Jev 留在哪里？

      Codex 的事件流、用户提问、turn/steer 和 turn/interrupt 承载输出与输入。现有追加输入与停止可复用；问题级别、任务卡内容和开场质量仍由当前 Harness 与平台契约定义。

      目标输出主线不依赖 Jev。现状中的表情与群消息分流、清单 Gate 要分别调整；Auto 模型档位选择作为独立功能另评估。

      DevDay 的 MCP Events 是外部事件订阅与唤醒能力。它不会自动生成这里的任务卡和反馈规则；现有飞书接入不因本规划自动更换。
