# Amber 用量试点

状态：2026-09-30，单人试点；尚未纳入常规主题或 `main`。

## 当前呈现

- 仅指定 Person 选择 **Amber** 时显示。切换到其他主题，两个用量入口都隐藏，侧栏恢复原布局；切回 Amber 后读取或刷新数据。
- 宠物旁显示当前实例 Codex 账号的额度窗口：默认收起为「本周剩余 xx%」，点击可看 5 小时/每周窗口、重置时间与采样时间。只有账号版本一致且采样足够新时显示百分比。
- 每个有记录的会话在标题行右侧显示累计 Token，例如 `12.4k`；选中或悬停时，重命名、归档、置顶按钮排在下一行。悬停数字可看精确值。无记录不显示数字，也不伪装为 `0k`。
- 额度、会话累计 Token、上下文占用是三个不同指标；本试点只呈现前两者。额度代表**实例登录的 Codex 账号**，不代表这个 Person 独享的额度。

## 数据与实现

- 额度：`/api/codex-auth/status` 与 `/api/codex-auth/rate-limits`；仅在 Amber 下读取，沿用账号版本和采样新鲜度检查。
- 会话累计：`/api/usage/summary?days=3650&top=5000` 的 `bySession.totalTokens`；仅在 Amber 下读取。数字包含该会话已记账的后台调用，不是剩余额度、费用或当前上下文占用。受账本覆盖、时间窗与前 5000 个结果限制；无记录保持空白。
- 两个数据读取逻辑分别位于 `static/chat/pet-quota-pilot.js` 和 `static/chat/session-token-pilot.js`；Amber 专属显示与位置集中在 `static/chat/amber-usage-pilot.css`。独立逻辑便于以后把数据能力从主题外观中拆出。
- 当前切换主题时即时显示/隐藏；浏览器重新可见和定时刷新只在 Amber 下请求。

## 进入常规主题前要解决

1. 在当前试点完成真实浏览器验收：桌面/手机、长标题、运行/未读/置顶/选中、无记录、主题来回切换、账号切换和接口失效。
2. 产品上决定「显示用量」是用户独立开关，还是各主题可选模块。主题应决定排版和色彩，指标含义、数据权限和刷新规则应保持一致。
3. 改用小型的会话用量接口，避免为侧栏下载完整账单摘要；明确时间范围、记录覆盖、过期状态及单位规则。
4. 对更多 Person 和常规主题验证信息密度与可读性，再决定默认开启范围。扩大范围前去掉单人硬编码并建立可控配置。

本文件记录试点与后续条件，不代表已批准面向所有人发布。
