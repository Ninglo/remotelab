标色规则与样本口径

Session 与自身同模型、同 Harness 的前台运行比较：最近 3 个已落账 Run 的均值，对此前最多 20 个（至少 10 个）的均值。达到 2 倍为黄色、3 倍为红色；同时至少增加 1 秒（执行 1 分钟）或 1 万 Token。基线为零或样本不足不标红。任务复杂度变化也可能造成偏高，标色只提示核对原因。

共享资源沿用原 Monitor 的固定阈值。这里仅展示异常，不发送告警、不触发补救；平均值旁保留样本量，明细可看 P95。

群与发起人

总数为未归档会话，加窗口内有用量的归档会话；当前状态以未归档列表为准。发起人表示这条 Session 的发起身份，不把后续参与者都算作发起人。群与人的汇总是两种视角，不重复累加。

用量总览

用量来自已落账 Run；进行中的消耗可能尚未落账。缓存输入是输入的子集，不能重复相加。估算费用不是订阅账单，也不是任务质量评分。

覆盖与缺口

  • 已接入可匹配 Request / Run 的阶段均值和 P95；模型逐次调用、工具完整阶段、API 到 Session 的关联、CPU / 内存 / I/O 趋势仍未覆盖。API 实例统计不可分摊给会话；没有可靠关联不显示零次。
  • Session 明细最多读取最近 500 条事件元数据；较早的上下文记录可能不在窗口内。仅展示最近回传上下文，不能当作此刻完整原生提示。
  • 页面按打开、窗口切换、手动刷新读取，不后台轮询，不调用模型。缺失与失败单独显示。
  • 仅使用允许的 GET 查询；不调用运行补齐接口，不发送告警、不重试通知、不触发补救。现有告警系统保持独立运行。
