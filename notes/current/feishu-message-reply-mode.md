# 飞书消息回复：独立配置模式

本模式在 Settings 的「消息回复机制」中单独配置。现有回复模式继续保留，默认没有任何群采用新模式。

## 从草案到采用

设置包括开工首条文字、是否允许任务清单，以及不发进展／文字进展／卡片进展三种选择。最终回复不能关闭；必要的追问与异常说明单独投递。简短答复仍可以直接给答案，主动参与群仍按原机制判断是否发言。

调整选项立即更新完整示例，不调用模型或向群发消息。「保存草案，不生效」只保存候选。人选择明确的飞书来源和群，保存后点击「确认生效」，才将该草案复制为生效版本。修改草案不会改变已经生效的版本。「恢复旧模式」让后续新工作恢复旧显示规则，保留草案和更改记录。

设置不改变群的参与、旁听、暂停、分流、Bot 身份或资源权限。不自动推广到其他群，不影响 Web 的消息展示。群看板和跨群按需阅读不在本次实现范围内。

## 完整消息过程

较长工作可以先发一条具体的开工文字，再根据实际范围提供验收清单，过程中按所选形式发布有用的新发现，最后独立投递结果。需要人回答的问题单独投递，不埋在折叠卡里。关闭开工文字，不改变已选定的回复话题。

文字进展作为新消息进入原话题。卡片进展默认折叠，有清单时更新清单原卡；没有清单时使用一张轻量进展卡，后续更新原卡。手动展开或折叠作用于同一张共享卡，保留最后接受的点击，不保存为个人习惯。没有新发现就不为展示而发进展。

允许清单不强迫每个问题生成清单。清单的验收状态、执行停止与最终回复送达分别判断。进展卡只表示执行过程，不伪装成任务验收。

## 接入与验证

`GET /api/message-reply-settings` 返回草案、生效版本及已记录的群目录。人类登录身份用 POST 提交 `draft`、`activate` 或 `legacy`，带 `expectedRevision`；后两种必须明确 `confirm: true`。服务身份不能激活。实例文件 `message-reply-settings.json` 独立于旧进展控制及任务清单启用文件。

普通人类飞书输入接受时保存配置快照，重复提交沿用原快照。正在运行的原生会话补充及同群分流交接保留所属工作的模式，避免一次执行混用新旧展示。原卡按创建时的模式继续维护。确认不重放历史进展，也不会补发已结束工作的新卡。

实现复用现有 Session／Request、原生消息事件、持久投递及卡片 worker，不增加前置模型判断。隔离入口 `tests/test-message-reply-mode.mjs` 覆盖 12 种组合、保存与确认分离、群范围、版本冲突、回退、去重、旧模式及独立进展卡。生产新模式默认不启用；真实飞书使用效果须在选定范围确认后单独观察。
