# 飞书消息回复：当前默认与自定义草案

Settings 的「消息回复机制」先展示正在使用的方式和本实例当前默认机制，再提供独立的自定义草案。没有明确应用自定义配置的群继续沿用实例默认，页面上勾选的草案不代表当前生效配置。

启用 `REMOTELAB_FEISHU_GROUP_MESSAGE_BASELINE=2026-10-07` 的实例，群进展默认更新原卡并发送文字消息，卡片可选择「卡片＋新消息」或「只更新卡片」；已经选择的会话继续沿用自己的选择。未启用此基线的实例保留清单卡内折叠进展的默认机制。页面通过只读接口读取实例基线，不把两种机制统称为「旧模式」。

## 从草案到采用

设置包括「发送首条文字回复」「需要时显示任务清单」和独立的「显示过程进展」开关。进展启用后，展示方式是以下三种，全部保留一张卡片：

| 方式 | 卡片中的进展 | 独立文字进展 |
| --- | --- | --- |
| 卡片＋单独文字进展 | 随更新显示最新一条 | 在原话题逐条发送 |
| 卡片展示最新进展 | 新进展替换上一条，只显示最新一条 | 不发送 |
| 卡片展示全部进展（默认折叠） | 完整记录默认收起；展开后较多时在原卡内翻页 | 不发送 |

第一种对应本实例当前默认的进展投递形式；自定义草案的初始选择也采用第一种。是否需要进展不作为第四种展示方式。首条文字是收到较长任务后说明理解和第一步的回复。最终回复不能关闭；必要的追问与异常说明单独投递。简短答复仍可以直接给答案，主动参与群仍按原机制判断是否发言。

调整选项立即更新完整示例，不调用模型或向群发消息。页面按当前状态、草案选项、群范围、完整示例、保存与应用的顺序展示。「保存草案（暂不应用）」只保存候选。人选择明确的机器人来源和群，保存后点击「确认应用到选中群」，确认窗口列出所选群及已保存的选项，才将草案复制为生效版本。修改草案不会改变已经生效的版本。「改回当前默认机制」让后续新工作恢复实例默认，保留原有会话的进展选择、草案和更改记录。

设置不改变群的参与、旁听、暂停、分流、Bot 身份或资源权限。不自动推广到其他群，不影响 Web 的消息展示。群看板和跨群按需阅读不在本次实现范围内。

## 完整消息过程

较长工作可以先发一条具体的开工文字，再根据实际范围提供验收清单，过程中按所选形式发布有用的新发现，最后独立投递结果。需要人回答的问题单独投递，不埋在折叠卡里。关闭开工文字，不改变已选定的回复话题。

三种方式有清单时更新清单原卡，没有清单时使用一张轻量进展卡。后续更新、较晚出现的清单和重启都继续复用原卡。第三种从完整进展记录取内容，不裁成最近十条，不在折叠区之外额外展示最新一条；页码、展开和折叠选择作用于同一张共享卡，保留最后接受的点击，不保存为个人习惯。翻页观察与展开点击分别记录。没有新发现就不为展示而发进展。

允许清单不强迫每个问题生成清单。清单的验收状态、执行停止与最终回复送达分别判断。进展卡只表示执行过程，不伪装成任务验收。

## 接入与验证

`GET /api/message-reply-settings` 返回草案、生效版本、实例默认机制及已记录的群目录。人类登录身份用 POST 提交 `draft`、`activate` 或 `legacy`，带 `expectedRevision`；后两种必须明确 `confirm: true`。服务身份不能激活。实例文件 `message-reply-settings.json` 独立于原有进展控制及任务清单启用文件。

普通人类飞书输入接受时保存配置快照，重复提交沿用原快照。新确认使用 version 2 配置；已接受的 version 1 请求及原 `card` 设置继续按原方式处理，不静默迁移。正在运行的原生会话补充及同群分流交接保留所属工作的模式，避免一次执行混用新旧展示。原卡按创建时的模式继续维护。确认不重放历史进展，也不会补发已结束工作的新卡。

保存成功后，固定设置选项进入现有使用分析：草案与各群实际生效状态分别保留，重复保存和重复应用不增加切换次数，改回默认及移出生效范围单独可见。既有配置只建立采集起点的现状，不伪造过去的选择次数。统计与卡片阅读、进展点击放在同一入口；某个选项被开启或改回本身不能证明好坏，也不会自动改变用户设置。完整口径见 [使用记录](usage-instrumentation.md)。

实现复用现有 Session／Request、原生消息事件、持久投递及卡片 worker，不增加前置模型判断。隔离入口 `tests/test-message-reply-mode.mjs` 覆盖原 version 1 组合、新三种方式、清单可选、保存与确认分离、群范围、版本冲突、回退、投递去重、完整记录分页、按钮回调及快速更新缓存。生产自定义模式默认不启用；真实飞书使用效果须在选定范围确认后单独观察。
