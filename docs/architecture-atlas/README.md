# RemoteLab 架构图谱

这是供讨论和持续核对的架构导航网站。首屏以一条输入从发出到结果、再到轮后使用的七个阶段为主线；网页、飞书新旧规则、固定命令和定时日报套用相同的五个问题：用户看到什么、谁处理和判断、写入哪里、消耗什么、经过哪个接口。第二层用同一阶段的横向矩阵对照各入口；机制索引和证据层负责继续追到代码。网页没有把实例内部原文、凭据或群标识公开。

## 本版范围

- 源码基线：`811d153a8bd5084898f8f3430c8c77d22ebf3220`。
- 实例事实：只保留经本次读取的概括性配置与运行记录，未包含敏感标识；它们可能随实例变化。
- 飞书配置快照：所核对的 Bot 配置含 2 个旧版 quickReactions 群、1 个新版 jevReactions 试验群；新规则只覆盖该群主线。已读回一条 silent 观察记录及对应的 Session 用户事件、决策事件。这个样本不证明每条消息都成功送达表情。
- 主线当前提供六条已核对的入口样本，不声称覆盖所有连接器和命令；新增入口应补同一组阶段与横向标记。
- `源码已核`表示源码中存在相应实现，不等于生产进程已加载，也不证明某次交付成功。
- `配置已核`表示曾读取相应实例配置；`运行记录已核`表示曾读到执行记录；`设计方向`与`待核验`不能作为已上线能力引用。
- 资源快照于 2026-09-29 13:07 中国时间读取。目录大小来自 `du -sB1 -L`，对迁移后的链接取目标目录；模型用量来自最近 7 日 `queryUsageLedger({ days: 7 })` 汇总。静态页不会自动更新这些数值。账本不覆盖连接器单独调用的 Jev 快速判断，也不代表提供商账单。

## 更新方法

1. 在 `journey-data.js` 更新主线阶段或入口分叉。每个入口都必须覆盖同样七个阶段，每阶段填齐用户端、处理与判断、持久状态、资源、协议、代码入口及横向对照标记；跳过 Run 时明确写出为何跳过及后续交付。阶段编号是阅读坐标，实际并行与先后关系写在各入口的说明中。
2. 在 `experience-data.js` 更新深入场景、飞书规则、资源快照；在 `atlas-data.js` 修改机制节点、跨轮路径和证据状态。节点 ID 应保持稳定，主线源码锚点要能打开。
3. 核对源码入口是否仍存在、行号是否有效，再更新页面上的源码基线和日期。实际部署版本与实例配置要单独读回。
4. 使用一条真实案例串联 Request、Run、结果投递和外部回执；只有完整证据才能把“待核验”改成“运行已确认”。
5. 发布前检查所有静态资产，不能包含群 ID、会话 ID、凭据、内部 URL、用户原文或其他不适合公开的实例数据。
6. 覆盖同一公开 slug 时，同步更新 `index.html` 的脚本/样式查询版本和 `app.js` 的数据模块查询版本；公网缓存会保留旧资产，不能只替换文件。对已打开旧页的用户，提供带新查询版本的入口 URL。

本目录是静态 HTML、CSS 和原生 JavaScript，可以直接由静态站点服务提供。网站的源码入口指向此版基线，后续更新时需一起调整。
