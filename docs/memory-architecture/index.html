01 / 现有读取机制

每次开工，哪些内容会进来？

已核实的调用链

先区分新线程、续接与重建。实线表示自动提供或复用；虚线表示 Harness 根据当前任务读取。点击节点查看它的用途和来源。

还有哪些来源？怎样知道 Agent 实际读了什么？

Harness 自身的系统指令、工作区 AGENTS.md 和原生记忆属于另一条加载链路。RemoteLab 不声称完整捕获这些内容。平台 Context 事件证明传入的内容；工具读取记录证明本轮读过正文，文件存在或启动指针存在都不能替代读取证据。

连接器可按配置附加近期讨论、关联项目消息。配置的 Jev 路径还可从有出版回执与正文 hash 的日报选择有界片段。它们都不是所有 Session 的固定输入。可选的启动知识探测也不是本地记忆检索。

04 / 长期目标

像 PMO 一样看进展，也看工作的方法。

目标与示意，尚未上线

PMO 是跨项目协调与推进的职责。Agent 持续核对真实进展、找遗漏与依赖、发现重复工作和优秀方法，并向对应负责人提出有依据的建议。人的优先级取舍、责任承诺与现实验收分别保留。

当前实例 / 按需读回

我们登记了多少个人？

可在登录后读取当前实例的登记数量。本页不保存或发布真实名单与私人偏好。登记 Person 数量不等于去重后的组织人数或活跃用户数。

尚未读取打开 RemoteLab 登录

已具备：Person 登记、个人 Session 视图，以及语音快捷键、输入模式等产品设置。待建设：协作偏好的逐人来源、适用范围与确认，项目成员职责和去重身份。默认设置不等于本人明确认可；未知偏好标记未知。

认可由谁来确认？

按事项性质选择相应职责，不让每个人逐条点所有内容。确认与条目版本绑定，无回应保留待确认。

版本确认 / 示意

全覆盖，分步启用。

第一阶段就归集全部已登记项目；业务动作后续启用。验收可抽查质量，采集覆盖保持全项目。
