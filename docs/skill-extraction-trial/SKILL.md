# 单人 Skill 提炼试用

目标是让后续任务得到可证明的帮助。普通操作流程、泛泛总结、一次成功、调用次数都不足以说明值得新增 Skill。没有合适候选就不提示；不规定每天产量。设置公开和其他人加入都等待试用后的明确决定。

## 先看当前状态

RemoteLab 路径：读取 `${REMOTELAB_CONFIG_DIR:-$HOME/.config/remotelab}/skill-extraction-trial.json`；要求 enabled=true、version=1、personId 等于本条已核发言人，不从话题创建者或 Unix 用户名推断。没有策略、关闭或身份不匹配时不主动提炼，旧历史不能代替当前设置。

个人 SSH Codex 路径：仅在本人专用工作区明确安装此试点指针时，读该指针指定的本地策略；当前账号、工作区必须与策略绑定一致。不得按同机其他账号推断身份或复制启用设置。

策略提供 workspace（本人的试验草稿位置）、catalog（既有方法目录）、creator（本环境可用的创建方法）与 source（本次试用授权）。不载入全部 memory、Skill 原文或人员档案；只沿候选相关线索读取。

## 发现与确认

利用当前任务已获得的材料判断，不另开逐轮后台模型。值得候选的典型信号是：经过证据验证的非直觉原因、反复纠正后稳定下来的判断、能避免已知错误且换任务仍适用的操作方法。

先查 catalog 的名称和简介，再读真正相近的原件。明确新建、修改已有、合并，或无需 Skill。名称不同但触发、输入、决策和输出相同，通常应更新原方法。仅材料尚缺时，先保留线索，不弹出含糊建议。

在 workspace/candidates/<稳定候选名>/candidate.json 保存一份简短原件；更新同一候选，不另建项目主账。记录 version、owner、status、来源话题/原输入或文件、解决的问题、证据、适用/不适用条件、相近方法与处理决定、价值假设、拟制作范围、预先选定的验证标准。status 初始为 pending，actualUtility 初始为 unknown。相关来源内容或方案实质变化才升级版本。

检查 workspace 中相同候选的 pending/rejected 状态；没有新证据不重复询问。使用当前 Harness 原生异步问题展示一个具体候选，包含拟解决的问题、价值依据、与现有方法的关系，并明确“生成并验证，仅本人试用”。选择为生成并验证、调整方向、暂不生成。原任务继续；如果只有阻塞式提问，等原任务完成或可暂停处再提问。SSH 终端没有弹窗能力时使用原生终端提问，不假称飞书已弹窗。

只有实际收到本人的明确选择才改 approved，保留其原话、真实来源请求/事件、候选版本和允许的范围。其他人的话、模拟测试答案、旧版本按钮、沉默、Agent 自己的判断均不批准。新输入与候选无关时不消费确认。重复确认沿既有草稿继续，不重复生成。拒绝写 rejected；修改方向更新候选后重新确认新内容。关闭试用停止主动建议与尚未执行的自动制作，保留历史和草稿。

## 制作

确认后才读取策略中的 creator，按该方法创建 workspace/candidates/<候选名>/draft/<skill-name>/。读取 [evaluation.md](evaluation.md) 决定所需验证材料。制作不阻塞原任务交付；按真实承接能力在原话题继续，不捏造后台执行或另起公共会话。

正文保留真正改变判断的经验、可执行步骤、输入输出、条件边界和失败处理；必要的长材料与脚本放 references/scripts 按需读取。去掉私人路径、凭据和特定案例里无法推广的个人要求。保留真正提出人、经验来源、整理者的不同角色；证据不足写待追溯。

格式验证仅检查包装；按评价规则运行实际例子。失败修订有界进行，记录未解决项，不靠无限改题或删失败样例凑通过。只有检查链接、依赖、触发与执行均通过，才能标 trial-ready；缺证据仍是 draft。原方法修改先在本人的草稿中生成差异，不覆盖共享原件。

## 本人试用与回传

回到候选来源话题说明生成了什么、实测增益与未验证之处，给出原件位置。本人批准的试用范围内可接入其原生 Skill 发现目录，保留旧版本与撤销方式；不会自动安装到其他账号或共享区域。

在 candidate.json 保留 outcome 与 evaluation.json 指针、使用反馈；后续明确反例更新同一原件。候选、草稿和评估材料不进入公共表格或全员日报。现有 Skill 目录同步不受影响。单人试用几天后，由本人决定是否扩大试点、发布共享原件或显示公共设置按钮；时间过去或生成了一条都不自动扩大范围。

正式发布若另获授权，复用既有共享目录、发现入口、多维表格和04:00日报链路；逐项核验发布与可调用，监控不在本试点中新增。

## 参考方法与取舍

- [Claudeception](https://github.com/blader/Claudeception/blob/main/SKILL.md)：借用非平凡、可复用、有验证的筛选和优先更新已有方法；不照搬产量或耗时门槛。
- [Anthropic skill-creator](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)：借用有／无 Skill 对照、触发正反例和人工反馈；使用本环境实际执行器，不安装其 hooks 或假定 claude CLI 可用。
- 创建格式及资源组织以本环境现有 skill-creator 为准。以上是借鉴方法，不能证明本试点已产生业务增益。
