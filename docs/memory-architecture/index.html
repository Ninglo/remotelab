02 / 存储地图

一个 Session、一个群，分别留下什么？

选择对象，再对照现状与方案。下列是路径规则和维护位置，示例中的 ID 是占位符；没有将真实会话或群名单公开。

路径怎么读：“配置目录”默认是 ~/.config/remotelab；“记忆目录”默认是 ~/.remotelab/memory。实例环境变量可以覆盖这两个位置。“连接器 storageDir”由该连接器配置决定；project-knowledge/ 是独立的项目知识目录。<sessionId> 指具体 Session 的稳定 ID。

Harness 原生会话和记忆保存在其运行配置选定的 provider home，RemoteLab 保存恢复标识。平台事件、原生上下文和长期认识各有职责；查看完整执行证据时还要查对应 Run 和工具产物。

03 / 项目归属

先知道这件事属于谁，再决定写入哪里。

归属规则 · 待实施

群与项目的绑定给出默认范围；个人 Session 可以关联项目，同一个 Session 也可以涉及多个项目。侧栏分组方便查找，不能替代有依据的项目归属。

范围登记最少保留什么？

登记是一份后台关联关系：生成导航和连接器绑定，不新增一套独立的交互式项目产品。业务认识仍在项目主账，原始来源仍在原处。

指针怎么避免“找得到入口，找不到重点”？

查看目前已经运行的加载链路：新线程、续接和重建

自动提供位置与本轮来源，正文仍由 Harness 按需读取。实线表示自动提供或复用；虚线表示条件关系。点击节点可查代码依据。

还有哪些来源？怎样知道 Agent 实际读了什么？

Harness 自身的系统指令、工作区 AGENTS.md 和原生记忆属于另一条加载链路。RemoteLab 不声称完整捕获这些内容。平台 Context 事件证明传入的内容；工具读取记录证明本轮读过正文，文件存在或启动指针存在都不能替代读取证据。

连接器可按配置附加近期讨论、关联项目消息。配置的 Jev 路径还可从有出版回执与正文 hash 的日报选择有界片段。它们都不是所有 Session 的固定输入。可选的启动知识探测也不是本地记忆检索。

分类规则与实例

按内容的用途、适用范围和生效条件分类。不是把整个 Session 复制到一个文件，也不是所有有用信息都写入 AGENTS.md。选择案例，查看目标位置与保留边界。

写入与生效遵守这些规则

这些维护位置之间是什么关系？

它们按用途分工：导航、工作过程、项目认识、背景、操作方法和依据。不是六本逐级重复抄写的共识文档；日报也不是新的一层记忆。
