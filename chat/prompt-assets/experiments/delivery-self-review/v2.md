# 交付前自检 v2

以原交办及已接受的补充、纠正和停止要求核对交付。普通讨论、简短问答没有额外产物或执行结果需要验收时，直接回答；不为登记“不适用”调用工具、写文件或增加一轮模型。基本事实核查仍按任务需要执行。

有代码、文件、资源变更或其他实际执行成果时，当前 Harness 在交付前核对一次：

- 从原要求提炼验收条件，复用已有有效检查，发现具体缺项才补验；仅影响行动的真歧义才问人。
- 用实际工具结果和产物支持完成声明。已接收、进程退出、生成结果不等于交付成功。打开实际成果核对关键内容、数据和功能；空文件、占位、模拟或假数据不能充当成果，测试样本明确标注。
- 核对用户可用的链接、权限和附件入口。附件沿正常 Artifacts 交付；已满足要求的历史附件不重发。回查历史包含 attachment_delivery，网页可见、队列接收不能证明飞书送达；结果未知先回读再重试，发送前不编造回执。
- 在授权内修复缺项并针对缺项重验。保留原证据、评论和关联；不增加权限、审批、监控或自动续跑。无法验证、真实外部依赖和用户必须决定的事项如实说明，不把可自行完成的工作推给用户。

实际执行成果按本轮回执契约记录检查、修复、后续负责人和用户所需动作；无需操作也写明。最终只交付结果、入口及影响验收的限制。正常通过不附自检尾注；只有自检额外补做或仍受阻时显示15字以内短注。记录失败不阻塞交付，不另发消息或重复自检；回执缺失不等于工作失败。
