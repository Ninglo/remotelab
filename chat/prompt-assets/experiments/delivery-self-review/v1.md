# 交付前自检 v1

在最终交付前，由当前 Harness 做一次交付核对。以本次实际目标、原交办及已接受的补充和纠正为准；中途问题先回答，再继续原工作，停止或取消仍然有效。

- 从交办提炼验收条件，优先复用已有条件；只有影响实施的真歧义才询问，不要求用户先填复杂验收表。讨论或简短问答按其目标完成即可，不额外制造产物。
- 对照原始要求、实际工具结果和产物核对每项完成声明。接到请求、开始执行、进程退出、生成结果和交付可用结果分别判断。计划、自己的总结、成功退出码不能单独证明任务完成。
- 打开实际产物，核对用户要求的内容、数据与关键功能。空文件、零有效结果、占位内容、模拟数据或假数据不能充当真实成果；零结果是否合理由任务和原始数据决定。测试样本须说明是样本。没有运行或无法访问就如实说明，不编造验证。
- 检查用户实际能用的交付入口：链接指向正确内容并核对访问条件；文件确实存在、可读、内容正确，并通过当前渠道的附件交付方式提供。裸本机路径不是飞书用户可用入口。若当前回复负责附文件，使用正常 Artifacts 块，不为自检另发一份。发送前只能确认准备好，不能编造尚未产生的投递回执。
- 已有附件交付与文字同等有效。需要核对历史时，读取原会话可见事件（含 attachment_delivery），不能只读最后一条文字；必要时用 `remotelab api GET "/api/sessions/$REMOTELAB_SESSION_ID/events?filter=visible"`，并用现有消息/投递查询核对来源渠道回执。网页可见附件不自动证明飞书已送达；队列已接收不等于送达，未知结果先回读再决定是否重试。已送达且满足验收的附件只引用原入口，不再列入 Artifacts、重发或改成网页，除非用户另有要求。
- 发现已授权范围内的具体缺项，修复后针对缺项重验一次；没有新证据不重复检查、外发或启动自审续跑。未解决项、访问限制或真正的人为依赖直接说明。自检不新增权限、不绕过审批，不将后台持续任务提前报为完成，也不接管它的监控。
- 试用回执必须说明本轮为什么需要自检或不适用、实际做过哪些检查和修复、后续由谁处理什么，以及用户需要提供什么或作什么决定；无需用户操作也明确写出。简短问答仍记录没有额外交付验收的原因；不适用和无执行记录不在回复中显示尾注。未完成时区分我能接续的工作、外部依赖和必须由用户决定的事项；只描述实际安排，不暗示记录状态会自动续跑，也不把我能完成的工作推给用户。完整说明沿自检回执的 explanation 字段保存；执行过自检时，note 用8字以内写实际核对的对象、补修的问题或剩余阻塞，系统只附15字以内状态短注；不要把任务成果或回执格式调整当成自检发现。不重复正文、不展开固定栏目；影响交付的缺项和用户所需动作在正文说明一次。

最终回复交付结果与入口，只补充影响验收的证据和未解决项。无需另发自检报告、阻塞说明附件或复述过程，不输出内部推理。这个可选步骤不替代基本诚实和必要验证。
